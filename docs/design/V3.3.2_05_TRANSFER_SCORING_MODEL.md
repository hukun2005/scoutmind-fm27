# V3.3.2-05-03 引援机会评分模型

- 实现：`backend/app/services/transfer_radar.py::_score_entry`
- 适用范围：机会雷达列表、详情与排序；不是"球员能力评分"的替代品
- 原则：可解释、确定性、缺失即 `NULL`，不把未知当 0

## 1. 四个维度

| 维度 | 权重 | 计算 | 缺失条件 |
|---|---|---|---|
| 球员实力 `ability_score` | 0.35 | `clamp((ca - 40) / 140 * 100, 0, 100)` | `ca` 为空 |
| 阵容适配 `squad_fit_score` | 0.25 | `100 * (0.6 * (1 - coverage) + 0.4 * (1 - depth_quality))`，取球员位置对应槽位 | 无用户俱乐部、槽位未知或阵容无该槽位 |
| 机会强度 `opportunity_score` | 0.25 | listed 85 / release 80 / loan_listed 75 / 合同 6m 80、12m 65、24m 50 / 推测 40；合同 ≤12 个月 +5；上限 100；推测封顶 45 | 恒有值（类型决定） |
| 财务可行 `financial_score` | 0.15 | 无预算来源 → NULL | 恒为 NULL（当前存档） |

位置解析：扫描器的多位置字符串（如 `AML, AMR, AMC, ST, MC`）按顺序取第一个可映射槽位；否则按位置组回退（GK/DF/MF/FW → GK/CB/CM/ST）。

## 2. 综合分与置信度

- 仅用可用维度，按原权重重新归一化：`overall = Σ(score × weight) / Σ(weight)`。
- `score_confidence = min(1, Σweight) × data_conf`，其中 `data_conf = 0.7 + 0.15（有身价）+ 0.15（有周薪）`。
- 全部维度缺失时不输出综合分，列表显示"—"。

## 3. 推荐分组

按顺序命中：

| 分组 | 条件 | 展示 |
|---|---|---|
| `strong` | overall ≥75 且 opportunity ≥70 | 强烈推荐关注 |
| `loan` | 类型为 `loan_listed` 且 overall ≥55 | 可租借机会 |
| `long_term` | 年龄 ≤21、PA−CA ≥15、overall ≥55 | 长期潜力目标 |
| `watch` | overall ≥60 | 值得考察 |
| `not_recommended` | 其余 | 暂不推荐 |

分组只影响排序与展示，不代表"游戏内一定能买到"。

## 4. 真实数据表现（存档 2）

- 已挂牌的顶级球员示例：Boubacar Kamara，CA 等级对应 ability 85.0、位置 DM/MC 对应槽位需求 100、opportunity 85 → overall 89.41，`score_confidence=0.85`（有身价与工资）。
- 分组分布（主机会 30,991）：strong 488、watch 7,030、loan 717、long_term 1,848、not_recommended 20,908。
- 用户俱乐部仅 17 人，多数槽位覆盖不足，`squad_fit_score` 普遍偏高；这是"阵容缺口大"的真实反映，不是评分 bug。
- 财务维度全部为 NULL：真实存档没有转会预算/工资预算来源，界面对应显示"—"并提示"财务可行性未计算"。

## 5. 使用建议

1. 先看 `strong` 与 `loan`，再按合同剩余排序排查"即将到期"的低价机会。
2. 详情抽屉同时展示四个维度与置信度；置信度低（<0.7）时不要只依赖综合分。
3. 进入报价工作台后，报价引擎会重新计算估值与预算；雷达评分不直接等于报价金额。
