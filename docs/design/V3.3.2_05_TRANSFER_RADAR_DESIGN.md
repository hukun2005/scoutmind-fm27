# V3.3.2-05-01 转会机会雷达设计

- 实现：`backend/app/services/transfer_radar.py`、`backend/app/api/routes_transfer_director.py`、`frontend/src/views/TransferDirectorView.vue`（机会雷达页签）
- 版本：`transfer-radar-1`
- 数据依据：`docs/reports/V3.3.2_05_TRANSFER_OPPORTUNITY_SOURCE_AUDIT.md`

## 1. 目标与边界

一次性扫描当前存档全部可读球员，把「已确认机会」与「AI 推测机会」分开呈现，并记录状态变化与提醒。

不做的事：

- 不把离队意愿伪装成可读：真实来源没有该字段，`summary.capabilities.transfer_intent = "unsupported"`。
- 不把出场少、年龄大直接写成"想离队"；规则推测只能进入 `ai_inferred`，`verified_status` 必须为 `inferred`。
- 不在页面加载时重复全量扫描；只有显式刷新或该存档尚无快照时扫描一次。

## 2. 扫描流程

1. 读取 `fm_saves.user_club_id` 与阵容需求（`analytics.squad.squad_overview`，复用缓存）。
2. 一次性取出所有 `player_instances`（`latest_snapshot_id` 非空），并批量取每人最新 `player_availability`（窗口函数按 `observed_at, id` 取第一行）。
3. 计算合同剩余：以该球员快照 `game_date` 为基准，缺失时回退存档内最大 `game_date`，仍缺失则不计入合同机会。
4. 生成候选：
   - `listed` / `loan_listed` / `release_listed`：字段为 `True` 才生成；`False` 是"已确认未挂牌"，`NULL` 是"来源未提供"。
   - `contract_expiring`：剩余 ≤ 24 个月，分桶 `6m/12m/24m`（≤6 记 6m，依此类推）；已过期按 0 个月计入 6m。
   - `ai_inferred`：仅在俱乐部可读且该队阵容 ≥5 人时启用两条规则（年龄 31+ 且合同 ≤24 个月；24 岁以下且 CA 高于同队均值 5 点）。用户自己俱乐部不生成推测机会。
5. 评分（见 `V3.3.2_05_TRANSFER_SCORING_MODEL.md`）并写入 `transfer_opportunities`。
6. 与上一轮对比写 `transfer_opportunity_events`：`discovered` / `withdrawn` / `reappeared` / `bucket_changed` / `inferred_changed`。
7. 生成提醒：新出现的挂牌/可租借/解约挂牌、合同 ≤6 个月且 CA ≥150、以及关注名单球员的新机会；每次最多 200 条，按评分截断。

## 3. 主机会与去重

同一球员可能同时有多个类型（如 `listed` + `contract_expiring`）。为避免默认列表重复，`is_primary` 标记一个主机会：

`listed > loan_listed > release_listed > contract_expiring > ai_inferred`

默认列表只查主机会；按类型筛选时展示全部条目；详情返回该球员全部机会。

## 4. 读取与刷新

| 操作 | 行为 |
|---|---|
| `GET /opportunities/summary` | 只读；该存档无任何机会行时自动扫描一次 |
| `GET /opportunities` | 只读分页；支持类型、分组、俱乐部、位置、年龄、搜索、排序 |
| `POST /opportunities/refresh` | 全量重扫，返回 scanned/created/updated/deactivated/events/alerts_created/耗时相关字段 |
| `GET /opportunity-events` | 变化历史分页 |
| `GET /alerts`、`POST /alerts/{id}/read` | 复用 `alerts` 表，按球员+类型+标题去重 |

刷新是同步调用，结果与统计一并返回，便于前端展示"处理人数/失败原因"。重复刷新幂等：无变化时不写事件、不重复提醒。

## 5. 真实数据实测（存档 2，62,229 人）

| 指标 | 实测 |
|---|---|
| 首次扫描耗时 | 18.7 s（本机 SQLite） |
| 二次扫描耗时 | 9.9 s，`created=0`、`events=0`、`alerts_created=0` |
| 生成机会行 | 35,086（主机会 30,991） |
| 已挂牌 / 可租借 / 解约挂牌 | 711 / 1,619 / 2,625 |
| 合同到期（≤24 个月） | 30,122 |
| AI 推测 | 9（仅 172 人有俱乐部，且多数球队不足 5 人） |
| 提醒 | 200（达到单次上限） |

## 6. 已知限制

- 俱乐部归属：真实数据仅 172/62,229 人有 `club_id`，列表显示"未知"，俱乐部筛选覆盖面极小。
- 离队意愿、预算、出场统计：数据源不支持，接口以 `unsupported` 明示，不参与评分。
- 首次打开真实存档会触发一次全量扫描（约 19 秒），之后只读；刷新按钮会再次全量扫描。
- 扫描是规则计算，不调用 LLM；相同输入结果确定，可重复验收。
