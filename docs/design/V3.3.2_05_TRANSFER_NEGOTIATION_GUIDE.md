# V3.3.2-05-07 谈判与复盘使用指南

- 实现：`backend/app/services/transfer_director.py`（状态机、事件、复盘），前端「报价工作台 → 谈判记录」
- 版本：`negotiation-review-1`
- 原则：只记录用户真实确认的谈判，不自动提交游戏内报价

## 1. 状态机

`DRAFT → PROPOSED → SUBMITTED → COUNTERED → ACCEPTED / REJECTED → COMPLETED`，另有 `CANCELLED`、`WITHDRAWN`。

- 终态（`COMPLETED/REJECTED/CANCELLED/WITHDRAWN`）不可再追加事件。
- 每次事件只追加，不修改历史；重复提交相同事件返回 `duplicate=true`，不重复入库。
- 方向：`purchase`（买入）、`sale`（出售）、`loan`（租借，本轮新增）。

## 2. 推荐流程

1. 在雷达或工作台选中球员，生成买入/出售/租借三套方案。
2. 以其中一套创建谈判：记录初始要价、备注（如"首轮试探"）。
3. 每次对方反馈/我方调整，记录事件与金额；系统累计轮次与最新报价。
4. 成交/失败后标记终态并填写最终费用、拒绝原因（可选）。
5. 点击「生成复盘」：对比初始估值、初始报价、最终费用，计算差额与百分比，并给出样本量提示。

## 3. 复盘口径

| 字段 | 含义 |
|---|---|
| `initial_valuation` | 谈判创建时的估值区间（样本不足时为空，不补数） |
| `initial_offer` | 初始报价 |
| `final_fee` | 最终成交/失败费用（用户填写） |
| `delta` / `delta_pct` | 最终费用 − 初始报价 |
| `round_count` | 事件轮次 |
| `completed_samples_in_save` | 本存档已完成谈判样本数 |
| `warnings` | 样本不足等提示 |

样本 <3 时明确提示"当前历史谈判样本不足，暂不形成可靠规律"，只展示事实，不生成策略结论。

## 4. 租借谈判

- 租借方案包含：租借费、工资承担比例、租期、买断选择权/强制买断、潜在总成本。
- 游戏内未标记 `loan_listed` 时仍可生成方案，但会带警告"游戏内未标记可租借，报价可能被拒绝"。
- 记录租借谈判时方向选择 `loan`，复盘口径与买卖一致。

## 5. 数据边界

- 不自动写入游戏存档、不自动提交报价。
- 未获取的条款保持 `NULL`，复盘不会用 0 填充。
- 完成的谈判会进入成交策略案例（`case_origin=negotiation`），供下一次相似匹配使用。
