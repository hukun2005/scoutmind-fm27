# ScoutMind FM27 V3.3.0 — UI 设计系统

风格：**Premium Dark Football Intelligence**（深海军蓝 · 青蓝强调 · 克制动效 · 中文优先）。

本文件不重建既有 Token，而是把现有 `tokens.css` / `base.css` / `element.css` 收敛为一套可执行规则。

## 1. 色彩

全部取自 `frontend/src/styles/tokens.css`，页面与组件禁止写死颜色。

| 用途 | Token | 使用规则 |
| --- | --- | --- |
| 页面背景 | `--sm-bg` / `--sm-bg-deep` | 全站唯一底色，不做整页高亮 |
| 卡片背景 | `--sm-surface` / `--sm-surface-raised` | 卡片略亮于页面，最多两层 |
| 边框 | `--sm-border` / `--sm-border-strong` | 低对比深蓝；发光边框只用于 hover / 焦点 |
| 正文 | `--sm-text-primary` | 标题与关键数值 |
| 次要文字 | `--sm-text-2` | 说明、单位 |
| 弱化文字 | `--sm-text-3` | 标签、脚注 |
| 主强调 | `--sm-accent-cyan` / `--sm-accent-blue` | 链接、选中态、主要按钮 |
| 成功 / 警告 / 错误 | `--sm-success` / `--sm-warn` / `--sm-danger` | 只用于状态，不用于大面积填充 |

规则：

1. 同类按钮在所有页面同色：主操作 = `el-button type="primary"`，次要操作 = 默认按钮，低频操作 = `text`。
2. 状态不能只靠颜色：必须同时给出文字（如「已完成」「未检测到游戏」）或图标。
3. 大面积区域只允许使用 `surface` 与低透明度渐变，不使用高饱和填充。
4. 文字与背景对比度：正文 ≥ 4.5:1，弱化文字 ≥ 3:1 且只用于非关键信息。

## 2. 字体与层级

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| H1 | `--sm-fs-2xl` / 600 | 页面唯一标题（中文） |
| H2 | `--sm-fs-lg` / 600 | 卡片标题 |
| 正文 | `--sm-fs-sm` | 列表、说明 |
| 辅助 | `--sm-fs-xs` / `2xs` | 单位、脚注、标签 |
| 数字 | `.sm-num` + `--sm-font-mono` | 指标、金额、评分 |

规则：页面标题只出现一次；顶栏面包屑（模块 / 页面）使用 `2xs` 弱化文字；英文只允许出现在品牌名（SCOUTMIND）、必要缩写（CA / PA / FM27）与技术诊断的开发者选项中。

## 3. 间距、圆角、阴影

- 间距：`4 / 8 / 12 / 16 / 24 / 32`（`--sm-space-1…6`），卡片内边距默认 16（`--sm-space-4`）。
- 圆角：控件 `--sm-radius-sm`，卡片 `--sm-radius-md/lg`，胶囊 `--sm-radius-pill`。
- 阴影：默认卡片 `--sm-shadow-1`；强调区（欢迎区、数据中心）`--sm-shadow-2`；不使用外发光替代层级。

## 4. 页面结构模板

每个页面最多 5 层：

1. 页面标题（中文）+ 一句说明 + 页面级操作（≤2 个）。
2. 一个主要操作区（搜索 / 筛选 / 同步按钮）。
3. 核心数据区（统计卡或列表）。
4. 辅助信息（一句脚注或链接）。
5. `<details class="sm-details">`：低频内容（图表、覆盖度、诊断、开发者选项）。

“更多筛选 / 更多分析 / 开发者选项”统一使用原生 `<details class="sm-details">`，默认折叠，展开后不改变主结构。

## 5. 组件规范

| 组件 | 规范 |
| --- | --- |
| `PageHeader` | 只渲染标题 + 说明 + `actions` 插槽；`eyebrow` 已停止渲染 |
| `FilterPanel` | 标题 + 说明 + 常用筛选（`.sm-filters` 栅格）+ `#advanced` 折叠 + `#actions` |
| `SmallField`（`.sm-field`） | 标签在上、控件在下；成对输入用 `.sm-field--pair` |
| `DataTable` | 支持 `#cell` 自定义列、`#empty` 自定义空状态；空状态必须携带动作 |
| `EmptyState` | 必须区分「无数据」「筛选无结果」「无权限」「未连接」；标题 + 原因 + 一个主按钮 |
| `ErrorState` | 展示归一化错误信息与「重试」；不展示堆栈 |
| `KpiCard` | 一个指标 + 一个单位/口径提示；可点击跳转；不堆叠多个数字 |
| `SectionCard` | 标题 + 一句说明 + `#footer`；同一页面同等卡片刻度一致 |
| `StatusBadge` | 颜色 + 中文文字，缺一不可 |

按钮状态：默认 / hover / 加载（`loading`）/ 禁用（附原因文字）/ 成功后 `ElMessage`。不允许无反馈按钮。

## 6. 动效

允许：卡片 hover 提升、按钮微光、页面淡入、图表平滑过渡、骨架屏。
禁止：持续闪烁、霓虹泛光、粒子、影响阅读的背景动画、操作延迟。

- 全部过渡使用 `--sm-dur-1/2` + `--sm-ease-out`。
- 已支持系统级 `prefers-reduced-motion`，并在「系统设置 → 外观」提供手动关闭（`html[data-reduce-motion="1"]`）。

## 7. 桌面端与响应式

目标分辨率：1280×720 / 1366×768 / 1440×900 / 1920×1080。

- 侧边栏在 <1180px 收起为抽屉；`topbar` 高度固定 `--sm-topbar-height`。
- 表格横向滚动由 `DataTable` 内部承载，页面本身不出现横向滚动条（已加入 Playwright 断言）。
- 欢迎区、卡片栅格在窄屏单列堆叠；主要按钮始终可见。
- 弹窗/抽屉宽度不超过视口 90%，内容区独立滚动。

## 8. 可访问性

- 所有图标按钮必须有 `aria-label`；表单控件必须有可见标签或 `aria-label`。
- `el-dialog` / `el-drawer` 使用 Element Plus 内置焦点管理；关闭后焦点回到触发元素。
- 状态点必须配合文字；图表提供 `aria-label` 与文字脚注。
- 键盘操作：Tab 顺序跟随 DOM；折叠区使用原生 `<details>`，支持回车展开。

## 9. 本次新增的样式原语（`base.css`）

`.sm-details`、`.sm-hint`、`.sm-section-label`、`.sm-filters`、`.sm-field`、`.sm-field--pair`、`html[data-reduce-motion="1"]` 降级规则。
