# V3.3.2-05 共享数据契约（AI Transfer Director）

- 版本：`transfer-director-1`
- 基线：`feature/v3.3.2-release` @ `723e1c9`；开发分支 `feature/v3.3.2-05-ai-transfer-director`
- 前置：`docs/reports/V3.3.2_05_TRANSFER_SOURCE_AUDIT.md`
- 原则：先复用、再扩展；只新增 migration；未知值一律 `NULL`/`UNKNOWN`，不填 0；估价 ≠ 成交价。

## 2. 枚举与取值

### 2.1 交易类型

任务书大写枚举映射到既有小写枚举（`protocol.TransferRecord.transfer_type`），不改变已发布取值：

| 任务书 | 现有取值 |
|---|---|
| PERMANENT | `permanent` |
| LOAN | `loan` |
| LOAN_WITH_OPTION | `loan_with_option` |
| LOAN_WITH_OBLIGATION | `loan_with_option` + 条款 `buy_option`（`status=triggered` 语义为强制） |
| FREE_TRANSFER | `free` |
| FUTURE_TRANSFER | `future`（status） |
| UNFINISHED | `pending` / `agreed` |
| CANCELLED | `cancelled` |
| RUMOUR | 不支持（无授权来源），不落库 |

### 2.2 交易状态

现有：`completed / pending / future / agreed / bid_rejected / cancelled / failed / unknown`。只有 `completed` 进入成交价统计。

### 2.3 报价与谈判状态

- `transfer_offers.offer_type`：`conservative` / `competitive` / `fast_close`（买入）；`quick_sale` / `fair_sale` / `max_value`（出售）。
- `transfer_offers.direction`：`purchase` / `sale`。
- `transfer_negotiations.status`：`DRAFT / PROPOSED / SUBMITTED / COUNTERED / ACCEPTED / REJECTED / WITHDRAWN / COMPLETED / CANCELLED`。
- `negotiation_events.event_type`：`draft_created / offer_generated / offer_submitted / counter_received / offer_revised / accepted / rejected / withdrawn / completed / cancelled / note`。

### 2.4 数据来源（沿用既有来源字符串）

`fm27_live_reader` / `fmsuperscout` / `game_export` / `local_import` / `user_confirmed` / `ai_estimate`。未知来源不得写入；`ai_estimate` 只能用于估值与报价，不能写入成交事实。

### 2.5 可信度

数值 `confidence ∈ [0,1]`；来源优先级（字段级）：游戏实际成交/合同 > Native Reader > FMSuperScout > 用户确认 > 公开来源 > AI 估值。AI 估值不得覆盖真实合同/成交字段。

## 5. 服务层契约（确定性）

模块：`backend/app/services/transfer_director.py`

| 函数 | 输入 | 输出 |
|---|---|---|
| `player_transfer_context(db, instance_id)` | 实例 | 合同、可用性、租借、历史转会、条款、估值、缺失字段 |
| `club_transfer_summary(db, save_id, club_id)` | 存档/俱乐部 | 买入/卖出/租入/租出/自由/未来/取消 计数与金额（按币种分开） |
| `compute_valuation(db, instance_id)` | 实例 | 复用 `analytics.valuation.estimate_value`；样本不足返回 `insufficient_sample=True` |
| `generate_purchase_offers(db, instance_id, budget?)` | 实例/可选预算 | 三套方案 + 每套依据/风险/缺失数据 |
| `generate_sale_offers(db, instance_id)` | 实例 | 三套出售方案 + 阵容/工资影响 |
| `create_negotiation(...)` / `append_event(...)` / `review_negotiation(...)` | | 谈判记录与复盘 |

算法版本：
- 估值：沿用 `valuation-1`；
- 报价：`transfer-offer-1`；
- 复盘：`negotiation-review-1`。

报价规则（可用字段才参与，缺失即跳过并记录 gap）：

1. 基准 = `estimate_value().mid`；样本不足时退回 `player_snapshots.market_value`，并标注"仅身价，不是成交价"。
2. 合同因子：<6 月 ×0.75、<12 月 ×0.88、≥36 月 ×1.05（与 valuation 的 `_contract_factor` 保持同一方向，报价侧更激进）。
3. 年龄因子：≤21 ×1.10、22–27 ×1.00、28–30 ×0.90、31–33 ×0.78、≥34 ×0.62。
4. CA 因子：以 140 为基准线性 ±0.5%/点，限制在 [0.7, 1.4]。
5. 挂牌/可售：`listed=True` ×0.9；`not_for_sale=True` ×1.15；未知不加成。
6. 三套方案：保守 = 基准 ×0.85（首付 100%）；竞争 = 基准 ×1.0（首付 60% + 分期 40%）；快速 = 基准 ×1.18（首付 100% + 5% 浮动）。
7. 预算：提供时校验 `immediate_payment ≤ budget`，超出只提示不可行，不改数字；未提供时输出"当前未获取可靠预算数据，报价方案不包含预算可行性保证"。
8. 币种：全部 `EUR`；遇到非 EUR 记录时不做换算，单独列出。
9. 同一输入必须产生一致输出（无随机数、无时间依赖）。

## 6. API 契约

前缀 `/api/v1`；`save_id` 由服务端按当前存档注入并校验归属（越权返回 404/403）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/transfer-director/overview` | 同步状态、最近交易数、合同更新数、条款解析数、未知/冲突数、存档 |
| GET | `/transfer-director/player/{instance_id}` | AI 交易分析聚合（合同/工资/剩余/状态/条款/历史/估值/推荐报价） |
| POST | `/transfer-director/player/{instance_id}/purchase-offers` | 生成三套买入方案 |
| POST | `/transfer-director/player/{instance_id}/sale-offers` | 生成三套出售方案 |
| GET | `/transfer-director/offers` | 方案列表（可按球员/方向筛选） |
| POST | `/transfer-director/offers` | 保存草稿 |
| GET | `/transfer-director/negotiations` | 谈判列表 |
| POST | `/transfer-director/negotiations` | 创建谈判 |
| GET | `/transfer-director/negotiations/{id}` | 详情 + 事件 |
| POST | `/transfer-director/negotiations/{id}/events` | 记录事件（幂等） |
| GET | `/transfer-director/negotiations/{id}/review` | 复盘 |
| GET | `/transfer-director/club-summary` | 我的俱乐部买入/卖出/租借汇总 |

所有金额字段可为 null；响应带 `sources`、`missing_fields`、`warnings`（中文、面向普通用户）。

---

## 7. 身份、隔离与缓存

- 所有读写必须带 `fm_save_id`；实例必须属于当前存档。
- 球员身份使用 `player_instance_id`；跨存档不合并。
- 写入后调用既有查询缓存失效（`app/services/query_cache.py`），避免旧列表数据。
- 谈判与报价属于用户数据：`source=user_confirmed` / `ai_estimate`，不得回写游戏内事实字段。

## 8. AI 工具契约

新增工具（服务端注入 `save_id`，拒绝模型传入 `save_id`/`fm_save_id`）：

`get_player_contract`、`get_player_transfer_history`、`get_club_transfer_history`、`get_transfer_clauses`、`get_club_financial_context`（无预算来源时返回 `available=false`）、`calculate_transfer_valuation`、`generate_purchase_offers`、`generate_sale_offers`、`record_negotiation_event`（仅记录，不提交游戏内报价）、`review_negotiation`。

AI 只解释确定性引擎输出；不得生成金额。
