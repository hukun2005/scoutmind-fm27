## 2. 调查过程

1. 检查布局：`FM27_1_Layout` 中合同相关字段只有 `CON_EXPIRY`、`CON_SQUAD_NUMBER`、`CON_TEAM`、
   `CON_WEEKLY_WAGE`、`CON_STATUS_FLAGS`，**没有合同类型或对象 ID 字段**。
2. 检查定位方式：`PERO_FULL_CONTRACT` 指针指向的对象被当作合同；没有校验对象类型。
3. 检查解码：`FmDate.Decode` 对 32 个值都成功解出年份与序日，说明**不是**格式错误、也不是指针读空。
4. 检查分布：异常年份不是随机噪声（24/32 集中出现），更像同一指针在不同对象类型上指向了不同结构。

## 3. 可能根因（按可能性排序）

1. **同一指针指向多类对象**：标准合同、租借/试用、职员合同或条款对象可能共用 `PERO_FULL_CONTRACT`，
   但 `CON_EXPIRY` 偏移在非标准对象上对应另一个字段。
2. **`CON_EXPIRY` 不是所有合同类型的到期日**：部分对象可能把"开始日期/选项日期/解约金日期"放在同一偏移。
3. **混合对象池**：探测按球员抽样，未按对象类型分层；异常比例被整体比例掩盖。
4. 偏移本身错误的可能性较低：32/32 都能解出合法 FM 日期，说明字段确实是日期类型，只是语义/对象不匹配。

## 4. 本轮新增的诊断能力

1. `ContractDateDiagnostics.RawSamples`：输出最多 8 条 `0x原始值 -> y年份 d序日 [类别]`；
2. 合同探测新增 `contract_flags_mix`：按 `CON_STATUS_FLAGS` 统计合同对象状态位分布（仅作线索，不判定类型）；
3. `expiry_diagnostics` 详情现在同时包含分类统计、可解码比例与原始样本；
4. `Diag evidence` 可导出字段级证据 JSON，供后续按字段记录样本。
