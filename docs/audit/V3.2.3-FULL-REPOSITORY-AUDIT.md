## 4. 安全边界现状

- **UID 95% 阈值**：位于读取器布局验证/兼容清单；本次未降低、未绕过。
- **哨兵不得成为身份**：读取器、适配层、协议、Importer、模型、API 六处一致。
- **Canonical 只接收已验证身份**：unresolved 路径完全不触碰 canonical 表。
- **存档隔离**：所有 unresolved 查询与确认都带 `fm_save_id`，跨存档返回 404。
- **文件完整性**：信封/meta/manifest 三件套整体移动；不匹配整体隔离。
- **真实数据不外传**：`artifacts/`、`backend/data/`、`docs/evidence/*.json` 不含姓名/地址/PID。

## 5. 风险分级

### P0

1. 真实哨兵对象仍不在上游 dump 中——需要读取器直接枚举内存对象才能产生真实 Unresolved（数据源问题）。
2. 大规模导入仍同步执行：Agent 已改为"超时后核验完成度"，但后端没有后台 worker；44k 导入期间 HTTP 请求会占满。
3. 真实 FM27 的 1.1 信封、日期变化、多存档切换尚未在真实进程上验证（FM27 未运行）。

### P1

4. 前端缺少导入任务/进度页面；DataView 只展示质量摘要。
5. `docs/` 下报告较多，未统一索引入口。
6. Windows 一键安装/启动脚本未评估完成度。

### P2

7. 读取器 `date` 命令的日期来源/可信度尚未写入契约（后端字段已就绪，等待真实字段验证后再填）。
8. 多 worker 部署假设为单进程（启动恢复会把所有 `running` 任务判失败）——已在代码注释中声明。
