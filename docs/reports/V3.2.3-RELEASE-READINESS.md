# V3.2.3 发布准备结论

**结论：NOT_READY（不可发布）。**

原因不是代码质量，而是验收口径：任务书要求真实 FM27 闭环验收通过才允许 RC / 发布，
而本机当前 FM27 未运行，真实读取、真实 1.1 信封、游戏日期变化、多存档切换均未执行。

## 1. 已具备（代码与自动化）

- Unresolved 身份：哨兵不当身份、观察/候选/审计落库、审核 API、前端页面、Canonical 隔离。
- 读取器：`probe --report` 结构化 UID 诊断（计数、哨兵样本、扫描就绪度）。
- Agent：manifest + 双 SHA-256、三件套整体移动、`processing/`/`failed/`、重试携带边车。
- 后端：导入任务查询、启动恢复、运行中重复上传 409、拒绝码可查。
- 数据覆盖率：三层报告工具 + 真实证据（44,084 一致）。
- 数据库：SQLite 两个迁移 up/down/up；真实 44,084 库副本升级计数不变；PG 由 CI 覆盖。
- 测试：后端 497（494 通过 / 3 跳过）、.NET 191（51+129+11）、Playwright 9、前端构建通过。

## 2. 阻塞项（发布前必须关闭）

| # | 阻塞项 | 影响 | 关闭条件 |
| --- | --- | --- | --- |
| 1 | 真实 FM27 闭环未验收 | 无法证明真实内存 → 数据库链路 | 按 runbook 完成 probe/scan/import/重启/幂等，并记录真实数字 |
| 2 | 1.1 信封未在真实导入中记录 | 版本标记与读取器不一致（旧记录 1.0） | 重跑一次真实扫描导入，`import_jobs.schema_version=1.1` |
| 3 | 真实 Unresolved 为 0 | 审核链路只在测试数据上验证 | 需要读取器直接枚举无 UID 对象，或上游导出包含这些对象 |
| 4 | 导入仍同步执行 | 44k 导入占用请求 10 分钟以上；Agent 首次可能超时 | 后台 worker + 202 + 进度（SM-126B 完整版） |
| 5 | 游戏日期来源未在读取器落地 | 只能人工/后端登记来源 | 真实内存字段验证后填入 `date_source`/`confidence` |

1. 用户启动 FM27 并加载存档，按 `docs/runbooks/TOMORROW-FM27-LIVE-VALIDATION.md` 执行第 1–5 步（约 20 分钟 + 导入 10–15 分钟）。
