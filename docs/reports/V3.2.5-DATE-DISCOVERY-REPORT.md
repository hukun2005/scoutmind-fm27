# V3.2.5 日期候选发现报告（Phase 1）

## 1. 已实现

新增只读、有预算的日期候选发现链路：

```text
ScoutMind.Reader.exe date-discovery --expect <yyyy-MM-dd> [--json]
    ↓
GameBuildDetector → VersionGate → LayoutResolver
    ↓
WinMemorySource（只读）
    ↓
DateDiscovery：按区域分块读取，按 4 字节对齐扫描
    ↓
与期望日期逐位相等的 u32 候选（最多 64 个）
```

代码：

| 文件 | 作用 |
| --- | --- |
| `live-reader/ScoutMind.FMReader/Discovery/DateDiscovery.cs` | 编码/解码、区域扫描、预算、取消、候选上限 |
| `live-reader/ScoutMind.FMReader/Engine/FmDateDiscovery.cs` | 进程/版本/布局门控 + 结果状态 |
| `live-reader/ScoutMind.FMReader/Probes/IMemorySource.cs` | 新增 `Regions` 与 `TryReadBlock`（默认实现向后兼容） |
| `live-reader/ScoutMind.FMReader/Engine/WinMemorySource.cs` | 实现区域枚举与块读取（上游 `MemScan`） |
| `live-reader/ScoutMind.Reader/CliCommandParser.cs` / `Cli.cs` | `date-discovery` 子命令、`--expect` 校验、JSON 输出 |

## 2. 安全约束（与任务书 3.5 对照）

| 要求 | 实现 |
| --- | --- |
| 只读 | 全部经 `ReadProcessMemory`，无写接口 |
| 有区域边界 | 只用 `MemScan.ScanRegions` 给出的可读区域 |
| 有最大搜索量 | 默认 512 MiB（`DateDiscovery.DefaultMaxBytes`） |
| 有超时 | 默认 20 秒，逐块检查 |
| 支持取消 | `CancellationToken` 每块检查，取消写入诊断 |
| 发现游戏退出 | `TryReadBlock` 失败即跳过区域，不重试死循环 |
| 不可读安全失败 | 区域跳过并记录诊断 |
| 不猜偏移 | 没有预置偏移；只有与人工日期逐位相等的编码才算候选 |
| 地址不外传 | 地址只出现在本地 CLI 输出/诊断，报文与后端都不知道 |

## 3. 输出协议

```json
{
  "build": "26620374",
  "plugin_version": "27.1.0+2505117",
  "layout": "FM27_1",
  "process_detected": true,
  "expected_date": "2026-10-23",
  "encoded_value": 132776232,
  "candidate_count": 0,
  "candidates": [],
  "current_date": null,
  "date_source": "unknown",
  "verification_status": "game_not_running",
  "diagnostics": ["..."]
}
```

`verification_status` 只可能是：`game_not_running`、`unsupported_build`、`layout_not_verified`、
`blocked`、`unverified_candidate`。**单次命中永远是 `unverified_candidate`，不会出现 `verified`。**
