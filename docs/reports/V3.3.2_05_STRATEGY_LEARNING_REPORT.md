# V3.3.2-05 成交策略学习报告

- 状态：功能 **PASS**（案例推导/相似匹配/归纳）；真实存档策略结论 **BLOCKED_BY_SOURCE**
- 设计：`docs/design/V3.3.2_05_TRANSFER_STRATEGY_LEARNING.md`
- 实现：`backend/app/services/transfer_strategy.py`

## 1. 能力核对

| 要求 | 结果 | 证据 |
|---|---|---|
| 建立成交案例库 | PASS（功能） | 案例由 `transfer_history(status=completed)` + 费用组件 + 租借记录 + 已完成谈判推导，无新表 |
| 匹配相似案例 | PASS | 位置组/年龄/身价/合同/成交方式五维，返回 `match_pct` 与共同点、差异 |
| 归纳成交策略 | PASS（含样本门槛） | 7 类固定模式；<3 条标记样本不足，不下结论 |
| 引用真实案例 | PASS | 每条结论附 `case_ids`（最多 20 条，摘要引用前 5 条） |
| 样本是否足够 | 真实存档不足 | 存档 2 案例 0 条；演示存档 1 有 136 笔合成数据 |
| 区分游戏/现实交易 | PASS | 只读游戏内导入与谈判结果；`case_origin=demo/imported/negotiation`，不接入现实转会 |

## 2. 真实存档结果（存档 2）

```json
{
  "available": false,
  "message": "当前存档没有可学习的成交案例；策略结论保持为空，不虚构学习效果。",
  "total": 0
}
```

前端「成交策略」页签显示空状态并提示"可在数据中心导入 CSV/JSON"。这是数据源限制，不是功能失败。

## 3. 演示存档（存档 1）功能验证

- 151 笔历史转会，其中 136 笔 `completed`（117 永久、13 租借、6 免签），258 条费用组件。
- 全部标记 `case_origin=demo`，接口与界面均提示"演示数据仅用于功能验证"。

## 4. 单元测试证据

- 3 笔真实导入案例 → 案例总数 3、分期组件命中、相似匹配 >50%、共同特征含"位置组相同"；
- 分期模式样本充足（3 条），`case_ids` 非空；
- 1 笔演示案例 → 样本不足提示、`demo_cases=1`、整体提示演示数据；
- 空存档 → `available=false`。

## 5. 后续可提升项

- 真实存档需要导入历史转会 CSV/JSON 后才能形成策略结论；
- 当前身价维度依赖案例的 `player_value`（多数为空），匹配时以可用维度归一化，避免虚假相似度。
