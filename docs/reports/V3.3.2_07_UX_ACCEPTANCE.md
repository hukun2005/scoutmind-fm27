## 2. 实现要点

### A-01 首次启动引导

- 后端聚合 `/meta/bootstrap`、俱乐部关联健康、导入任务、活动后台任务与迁移版本，统一输出
  `checks[]`（`ready / checking / needs_attention / unavailable`）与 `actions[]`。
- 只在**检查成功且确实需要处理**（无球员或存在待处理项）时自动弹出；接口不可用或数据已就绪时不打扰用户，
  也不会阻塞其他页面（该行为由既有 Playwright 用例回归验证）。
- 已导入数据的存档不再显示可用的“开始导入”；可从设置页“重新打开首次启动引导”再次进入。

### A-02 数据中心

- 健康卡片展示存档、球员/俱乐部/转会/机会数量、状态等级、最后更新时间与后台任务数。
- `一键检查`：只读诊断，输出重复导入、悬空俱乐部引用、扫描新鲜度、失败任务；结果留在卡片内。
- `一键修复`：仅执行 `club_links`；`player_identity`/`contract`/`delete_duplicates` 返回 `skipped` 与原因，
  不删除任何原始数据；修复后清空查询缓存并刷新健康快照。
- 俱乐部归属不确定的球员继续保持 `MISSING_SOURCE_FIELD`，不按姓名猜测绑定。

### A-03 扫描进度

- `current_stage` 由后端统一映射（排队中/分析球员状态/更新机会/修复俱乐部关联等），前端不拼接内部状态机。
- `eta_seconds` 仅在 `RUNNING`、`processed >= 50` 且 `total > 0` 时计算；样本不足返回 `null`，不编造剩余时间。
- `resumable` 由任务类型或检查点决定，前端以“可继续”标签提示。

### A-04 错误与诊断

- 已知错误码映射为固定中文文案；未知码统一“系统暂时无法完成该操作，请稍后重试”。
- 测试断言响应体不包含 `Traceback`、`select ` 等内部信息。
