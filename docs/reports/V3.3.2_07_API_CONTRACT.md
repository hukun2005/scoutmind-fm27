# V3.3.2-07 API 契约

约定沿用仓库现状：

- 前缀 `/api/v1`，本地令牌可选（`X-ScoutMind-Token`）。
- 存档作用域：服务端从 `get_active_save` 解析，不接受请求体里的 `save_id`；越权统一 404。
- 业务错误体：`{"detail": {"code": "...", "message": "..."}}`（FastAPI HTTPException 既有格式）。
- 分页：`limit` + `offset`，返回 `{items, total, limit, offset}`。
- 新增字段一律"只增不改"，旧字段语义不变。

### POST `/api/v1/system/repair`

只执行安全修复；不安全项返回 `skipped` 与原因，不删除原始数据。

请求：

```json
{"targets": ["club_links"], "dry_run": false}
```

`targets` 目前只接受 `club_links`（复用 `club_linkage.repair`）。返回：

```json
{
  "dry_run": false,
  "executed": [{"target": "club_links", "scanned": 62229, "linked": 1172, "failed": 0}],

  "health": {...},
```

## 2. 后台任务序列化扩展（Agent 2）

`GET /transfer-director/scans`、`GET /transfer-director/scans/{id}` 与创建任务返回的 `task` 对象追加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `current_stage` | string | `排队中`/`分析球员状态`/`更新机会`/`修复俱乐部关联`/`已完成` 等，仅用户可读 |
| `eta_seconds` | int \| null | 仅在 `processed >= 50` 且 `total > 0` 时按已用时/已处理量估算；否则 null |
| `heartbeat_at` | string \| null | 最近心跳时间 |
| `resumable` | bool | 有检查点的扫描或关联修复为 true |
| `status_key` | string | 机器可读状态，等价现有 `status`，便于前端映射 |

现有字段（`progress/total/processed/matched/failed/message/cancel_requested/...`）全部保留。

## 4. 报价（Agent 4，扩展既有端点）

端点不变：

- `POST /transfer-director/player/{instance_id}/purchase-offers`（body 可选 `{"budget": number}`）
- `POST /transfer-director/player/{instance_id}/sale-offers`
- `POST /transfer-director/player/{instance_id}/loan-offers`
- `POST /transfer-director/offers/loan?instance_id=`
- `POST /transfer-director/offers?instance_id=`

响应追加：

```json
{
  "currency": "GBP",
  "currency_known": true,
  "currency_source": "transfer_history",
  "currency_note": null,
  "budget_status": "unknown|provided|insufficient",
  "budget_note": "预算状态未知，无法确认该报价符合俱乐部财政条件。",
  "strategy_adjustment": {
    "applied": true,
    "multiplier": 1.04,
    "before": 12000000.0,
    "after": 12480000.0,
    "sample_size": 4,
    "confidence": {"level": "preliminary", "label": "初步策略"},
    "case_ids": ["transfer:3", "transfer:7"],
    "basis": "相似成交案例的成交/估值中位数"
  },
  "offers": [
    {
      "offer_type": "conservative",
      "currency": "GBP",
      "currency_known": true,
      "strategy_adjustment": {"applied": true, "before": 10200000.0, "after": 10608000.0},
      "risk_level": "low",
      "rationale": {"reason": "...", "case_ids": ["transfer:3"], "adjustment": {...}}
    }
  ]
}
```

规则：

1. 无案例：`strategy_adjustment.applied=false`、`multiplier=1.0`，输出 `case_ids=[]`。
2. 案例少于 3 个或相似度不足：不调整，只展示案例引用。
3. 调整系数来自可配置权重与案例统计，必须确定性；倍数限制在 `[0.85, 1.15]`。
4. 金额不得为负；分期总和 + 即时支付 = 固定承诺。
5. 币种未知时 `currency=null`、`currency_known=false`、`currency_note="货币单位未知"`；存储占位 `UNKNOWN`，不转换。
6. `budget_status` 三态：未提供 / 已提供且全部可行 / 已提供但存在不可行方案。

## 5. 反馈（Agent 4）

### POST `/api/v1/transfer-director/feedback`

```json
{
  "instance_id": 101,
  "direction": "purchase",
  "outcome": "completed|rejected|cancelled|negotiating|unknown",
  "amount": 9500000,
  "offer_id": 12,
  "negotiation_id": 3,
  "note": "对方接受分期",
  "source": "user_confirmed"
}
```

幂等键：`(save_id, instance_id, direction, outcome, amount, note)` 哈希。重复提交返回 `duplicate=true` 与首次记录，不重复计入统计。

返回：

```json
{"duplicate": false, "feedback_id": 5, "outcome": "completed", "learning_updated": true, "data_version": "...", "message": "已记录真实成交，将用于后续报价参考"}
```

规则：

- 只有 `outcome=completed` 且 `amount` 有效才写入成交案例（生成 `TransferNegotiation(status=COMPLETED, source=user_confirmed)` 或复用已有谈判）。
- `rejected`/`cancelled`/`negotiating`/`unknown` 只记录反馈，不进入成交统计。
- 写入后调用 `query_cache.clear()`，并更新 `data_version`。

## 6. 兼容性

- 不删除、不改名任何既有字段或端点。
- `TransferOffer.currency` 仍非空；未知时存 `UNKNOWN`，序列化时映射为 `null` + `currency_known=false`，老前端读到字符串不受影响。
- 既有 `strategy-cases`、`strategy-insights`、`strategy-cases/similar/{id}` 保留，返回结构只增字段。
