# V3.3.2-05 条款解析报告

- 结论：**本版本没有新增任何"自动条款解析"来源**。可解析的条款结构沿用扫描协议与导入文件；真实存档本身没有租借/买断/分期记录（0 条），因此自动解析状态为 `BLOCKED_BY_SOURCE`。
- 契约：`docs/design/V3.3.2_05_TRANSFER_CONTRACT.md` §1、§4

## 1. 可以表达/解析的条款类型

来源：`backend/app/ingestion/protocol.py` `FeeComponentRecord.type`（协议已存在的合法取值）

| 条款 | 支持状态 | 说明 |
|---|---|---|
| `base_fee` | 结构支持 | 基础固定费用 |
| `installment` | 结构支持 | 分期付款，可带 `due_date` 与新增 `payment_schedule` |
| `addon` | 结构支持 | 浮动条款，`condition` 记录触发条件 |
| `signing_bonus` | 结构支持 | 签字费 |
| `agent_fee` | 结构支持 | 经纪费用 |
| `loan_fee` | 结构支持 | 租借费，同时写入 `loan_records.loan_fee` |
| `sell_on` | 结构支持 | 二次转会分成，比例也可写入 `Transfer.sell_on_clause_pct` |
| `buy_back` | 结构支持 | 回购条款 |
| `buy_option` | 结构支持 | 买断选择权/强制买断（`has_option`/`has_obligation` 区分） |
| `wage_contribution` | 结构支持 | 工资承担金额/比例 |

条款状态沿用：`paid / scheduled / triggered / untriggered / conditional_unknown / unknown`。未知金额保持 `NULL`，`conditional_unknown` 表示条款存在但金额未知。

## 2. 本版本新增

1. `transfer_fee_components` 新增 `source`、`confidence`、`payment_schedule`，让每条条款都能说明来源与付款计划。
2. `loan_records` 新增 `loan_fee`、`wage_contribution_amount`、`wage_contribution_pct`、`buy_option_fee`、`buy_obligation_fee`、`option_status`、`confidence`。
3. 交易上下文接口 `GET /transfer-director/player/{instance_id}` 返回 `clauses`，每条带 `clause_type / clause_value / trigger_condition / payment_schedule / clause_status / source / confidence`。
4. 没有新建 `transfer_clauses` 表：条款属于费用组件，重复建表会造成双写与不一致。

## 3. 冲突与覆盖规则（保持现状，不静默改数）

| 场景 | 处理 | 证据 |
|---|---|---|
| 同一 `source_record_id` 重复导入 | 跳过，不覆盖原记录 | `importer._upsert_transfers`（`transfers_skipped`） |
| 状态从 `pending/future/unknown` → 其他状态 | 更新状态并追加 `transfer_status_history` | `importer._upsert_transfers` 新增逻辑 + 测试 |
| 已 `completed` 的记录再次导入不同费用 | 不覆盖；保持原值 | 更新分支只允许未完成状态迁移 |
| 条款金额未知 | 写 `NULL` + `conditional_unknown`，界面显示"未知" | 测试 `test_clauses_and_history_are_returned_with_provenance` |

## 4. 来源与可信度

- 条款只能来自 `local_import`（CSV/JSON）或 `user_confirmed`；`ai_estimate` 不允许写入条款事实。
- 真实存档计数：`transfer_fee_components` = 0（存档 2），`loan_records` = 0。
- 演示存档有 258 条费用组件，仅用于功能验证，不作为真实能力证据。

## 6. 未解决

- 自动从 FM27 内存读取条款仍不可行（外部扫描器无该结构）。
- 条款冲突没有自动合并策略：当前策略是"不覆盖"，需要人工复核时以导入源为准重新建记录。
