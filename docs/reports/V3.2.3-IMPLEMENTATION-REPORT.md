## 2. 关键改动

### 2.1 读取器（SM-124A）

- `ProbeModels`：新增 `UidDiagnosticsSummary`，`DiagnosticReport.UidDiagnostics` 从 integrity 探测的
  `ObjectIdDiagnostics` 派生；新增 `ScanReadiness`。
- `NativeScanBackend`/`IScanBackend`：暴露 `LastReport`；外部扫描器后端为 `null`（不伪造）。
- 新增 `ProbeReportWriter`：`probe --report <file>` 输出 `scoutmind.probe.diagnostics.v1`，
  含 `uid_diagnostics`、`sentinel_samples`、`sample_count`、`scan_readiness` 与完整 `report`。
- 现有 `probe --json` 输出保持不变。

### 2.2 数据覆盖率（SM-125）

- `scripts/data_coverage_report.py`：读取 probe 报告、上游 dump、协议扫描、SQLite 四类产物；
  逐层给出计数与 `differences`（原因：`upstream_not_exported` / `mapping_dropped_rows` / `rejected_rows` / `match`）；
  缺失层保持缺失，不补 0、不删行。
- 真实证据：`docs/evidence/data-coverage-report.{json,md}`（44,084 / 44,084 / 44,084，哨兵 0，差异 0）。

### 2.3 Agent 队列（SM-126A）

- `ScanManifest`（`scoutmind.scan.manifest.v1`）：信封 + meta + scan_id + 双 SHA-256/大小；缺失时补建，
  不匹配时整组隔离。
- `ScanQueue`：新增 `processing/`、`failed/`；`Claim/ArchiveAll/FailAll/QuarantineAll/EnqueuePending`
  都以三件套为单位；`EnqueuePending` 现在会带上 meta 与 manifest（修复真实验收里 `meta_missing` 被隔离的根因）。
- `SyncOneAsync`：先 claim，再校验/上传；只有后端确认完成才归档。

### 2.4 导入任务可靠性（SM-126B，部分）

- 后端：`GET /imports?scan_id=&status=`、`GET /imports/{id}`（拒绝码、`retryable`）；
  启动时把 `running` 任务标记为 `failed` 并写入 `interrupted` 行；同一 scan 在导入中重复上传返回
  `409 import_in_progress`，不再重启导入。列表与详情按存档属主校验：同一用户的多个存档可查，别人的存档 404。
- Agent：超时/传输失败后调用 `GET /imports?scan_id=` 核实：
  完成 → `sent/`；仍在跑 → `pending/`；失败 → `failed/`（含 `failure.json`）；400/422 → `failed/`。
- **未实现**：真正的后台任务队列（202 Accepted + worker + 进度心跳）。当前导入仍在请求内完成，
  因此 Agent 仍可能等待 60 s 超时一次，但不会再误判失败或重复导入。

### 2.5 游戏日期（SM-067，部分）

- 迁移 `b7e2c9d4a105`：`capture_runs` 增加 `date_source`、`date_confidence`、`date_read_status`（可空）。
- `POST /captures`：校验取值；`verified` 必须说明来源；无日期记为 `unknown/unavailable`；
  早于历史最新日期标记 `regressed` 且降级为 `unverified`；同 save+date+reader+scope+revision 仍更新原行。
- 读取器 `FmDateProbeResult` 尚未携带 source/confidence；在真实内存字段验证前不填 `game_memory/verified`。
