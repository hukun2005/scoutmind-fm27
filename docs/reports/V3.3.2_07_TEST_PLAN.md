# V3.3.2-07 测试计划

状态口径：`PASS` / `PARTIAL` / `FAIL` / `NOT_RUN` / `BLOCKED_BY_ENVIRONMENT` / `BLOCKED_BY_INFRASTRUCTURE` / `BLOCKED_BY_REAL_DATA`。
未执行不得写 PASS；没有真实数据时的学习验收统一标 `BLOCKED_BY_REAL_DATA`。

## 1. 测试原则

- 先写测试、后改实现；不删除既有测试、不降低断言、不跳过失败用例。
- 测试夹具中的成交案例必须显式标注为测试数据，不得包装成真实 FM27 验收。
- 所有报价断言验证"确定性 + 可解释 + 不编造"；所有学习断言验证"只用真实完成交易 + 存档隔离 + 去重"。
- 每个新增后端测试文件独立可运行，不依赖执行顺序。

## 4. 性能与容量

按钮/接口基准（本地 SQLite，单机）：

| 规模 | 指标 | 方法 |
| --- | --- | --- |
| 1,000 球员 | 全量扫描耗时、报价生成耗时 | `scripts` 或 pytest 计时用例 |
| 10,000 球员 | 同上 + 列表分页 P95 | 同上 |
| 60,000 球员 | 同上 + 内存峰值 | 同上，记录前后 RSS |

要求：报价生成不随案例数线性爆炸（案例上限截断）；列表接口不一次性返回全量；无 N+1（抽样 SQL 计数）。
