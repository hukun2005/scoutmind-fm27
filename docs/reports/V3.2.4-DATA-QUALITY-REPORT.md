# V3.2.4 数据质量与统计口径报告

本报告统一 V3.2.2.8 / V3.2.3 / V3.2.4 之间出现的 44,084、43,640、44,010、44,007 等数字。
所有数字都标注统计时间、存档、scan_id、数据来源与统计规则；差异不是“改数字”，而是不同时间点的真实数据。

统计规则：

- “扫描球员”= 扫描报文 `players` 数组长度；V3.2.4 起包含读取器枚举补齐的 unresolved 行。
- “导入实例/快照”= 数据库中该 scan 对应的 `player_instances` / `player_snapshots` 行数。
- “Unresolved”= `unresolved_player_candidates` / `unresolved_player_observations` 行数。
- 所有统计都是**同一存档、单次扫描**，不跨存档累加。

## 2. 为什么数字会变

1. **游戏状态变化**：玩家在两次扫描之间正常游玩（转会、青年队进出、合同到期），球员总数从
   44,084 → 43,640 → 44,497（V3.2.4 上游 dump 部分）。
2. **读取器对象枚举**：V3.2.4 的扫描在 dump 之后追加了读取器自己枚举到的无 UID 对象，
   本次网罗到 63,971 个球员对象，其中 3 个有姓名且无可用 UID（Pedro、Marcelo、Marcelo），
   另有 37 个无姓名对象只计数、不输出。
3. **不是重复计数**：3 条 unresolved 不进入 `player_instances`（哨兵实例 0），所以
   `44,007 + 3 = 44,010` 与扫描球员数一致。

## 4. 真实数据与模拟数据边界

- 真实：44,010 扫描、3 个 unresolved 对象、44,007 导入、审核 API 的 resolve/dismiss、重启持久化、重复上传幂等。
- 模拟（仅测试库）：哨兵/零 UID/同名不同 UID/无姓名对象/不可读对象/多存档隔离等边界，
  见 `backend/tests/test_unresolved_*` 与 `test_p1_security.py`，不写入真实验收结论。
- 未被真实覆盖：真实哨兵数量远小于 14（本次 3 个有姓名 + 37 个无姓名），
  以及“无姓名对象”的展示策略仍需产品决定。

## 5. 已知数据质量信号

- 合同探测：修复 1900 占位纪元后 `expiry_range` 与 `expiry_after_birth` 在真实样本上均为 17/17（100%），
  5 个“无到期日”按空合同排除，未降低阈值。
- 对象枚举：37 个无姓名无 UID 对象没有输出；这是有意的（不编造姓名），但意味着
  “真实 Unresolved 总数”不等于内存中无 UID 对象的真实总数。
- 重复对象：Marcelo 在对象枚举中出现两次（不同对象序号），已作为两条观察保留，未自动合并。
