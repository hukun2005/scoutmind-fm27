## 3. 关键设计结论

1. **不重写既有导入链路**：数据库写入仍由 `ScanImporter` 完成，`datahub` 只负责写前治理与写后验证。
2. **审计与业务同事务**：审计行在 `_apply` 内加入同一个 Session，任何失败一起回滚；重复导入不重复写审计。
3. **歧义不猜**：俱乐部名命中多个 uid 不补全；`foot` 之外的枚举只做大小写标准化；`rumour` 不会被改写为 `completed`；
   租借不会变成永久转会；未知费用不会改为 0。
4. **未知即未知**：无法枚举进程时 `detected=false`，不会谎报“游戏未运行”；版本无法读取时兼容性为 `unknown`。
5. **旧接口零改动**：`/imports/scan`、`/imports/fmscout`、`/imports/squad-csv`、`/imports/transfers` 保持原行为。

## 5. 已知限制（未超出本版本范围）

- 「同步游戏数据」按钮只做连接与安全判断，真正扫描仍由本机 `ScoutMind.LiveReader` 完成；
  当前安装包未内嵌读取器时，界面会明确引导用户使用「导入数据」。
- 阵容名单 CSV 由自动识别拦下并提示使用独立入口，不在本链路写入。
- 隔离记录当前提供查询与展示，不提供“一键重新归类”按钮（需要人工判断，避免错误自动合并）。
- 大批量（约 4.8 万行）会经历两次协议校验（引擎校验 + 导入器校验），以时间换安全边界；未做性能压测。

## 6. 结论

V3.3.0 已实现“一个入口、自动识别、自动修复、可审计、可回滚”的数据导入体验，未破坏既有导入契约与身份治理规则。
代码、迁移、测试、前端与文档均已落地；真实 FM27 端到端验收因环境不可用标记 `NOT_RUN`。
