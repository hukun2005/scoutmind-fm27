## 1. 哪些转会信息可以真实自动获取？

可以：

- 球员身份、俱乐部归属、位置、年龄、CA/PA、身价（真实存档 62,229 人，CA/PA 100%）。
- 周薪（50,509/62,229，81.2%）、合同到期日（51,539/62,229，82.8%）。
- 挂牌/可租标记（`listed` 1,558 行、`loan_listed` 6,491 行）。
- 已达成转会（agreed）标记（协议支持；真实存档 0 行）。

不可以（`BLOCKED_BY_SOURCE`）：

- 历史转会记录、成交费用、租借费、买断/强制买断、分期、二转分成、预算、传闻。

证据：`docs/reports/V3.3.2_05_TRANSFER_SOURCE_AUDIT.md`、`docs/reports/v332_05_realdata_verification.json`。

## 2. 哪些合同字段可以真实读取？

真实读取：`wage`（周薪）、`contract_end`、当前俱乐部、观测时间、来源、可信度、挂牌/可租/非卖标记。

不能读取（保持 `NULL`，界面显示"数据源不提供"）：合同开始时间、合同类型、奖金条款、解约金。

代码：`transfer_director._contract`；数据证据：真实存档 81.2% 有周薪、82.8% 有到期日。

## 3. 哪些租借条款可以真实识别？

**没有自动来源。** 真实存档 `loan_records = 0`，Reader/FMSuperScout 不提供租借费用、工资承担、买断条款。

系统具备表达这些字段的结构（`loan_records` 新增列 + `FeeComponentRecord` 的 `loan_fee/wage_contribution/buy_option/buy_back`），可接收导入或用户确认，但本轮无法在真实数据上验收。

## 4. 哪些字段仍然不支持？

历史转会、实际成交费用、转会类型自动判定、租借关系与费用、买断选择权/强制买断、分期付款结构（自动读取）、二转分成（自动读取）、俱乐部转会预算/工资预算、转会传闻、合同开始日期/合同类型/解约条款/奖金。

## 5. AI 买入报价是否能够运行？

是。`POST /transfer-director/player/{id}/purchase-offers` 输出保守/竞争/快速三套方案，金额全部由确定性规则计算；同一输入两次结果一致（测试固定）。

真实数据样本（CJ Olney，Brooklyn FC）：保守 2,507,884.33 / 竞争 2,950,452.15（首付 1,770,271.29 + 分期 1,180,180.86）/ 快速 3,481,533.54。

## 6. AI 出售报价是否能够运行？

是。输出快速出售/合理出售/价值最大化三套方案，并给出同位置队友数、缺口风险、年工资释放。真实样本：2,507,884.33 / 2,950,452.15 / 3,393,019.97（最高含 10% 二转分成）。

## 7. 是否支持分期付款？

- 报价层：支持。竞争方案固定费用 60% 首付 + 40% 分期；条款模型支持 `installment` + 新增 `payment_schedule`。
- 自动识别：不支持（没有来源）。

## 8. 是否支持附加条款？

- 报价层：支持浮动费用（5%/10%）与触发条件字段。
- 条款层：`addon`、`conditional_unknown` 状态、`condition` 文本。
- 自动识别：不支持。

## 9. 是否支持二次转会分成？

- 支持字段（`sell_on`、`Transfer.sell_on_clause_pct`）与出售方案中的 10% 二转分成。
- 自动识别：不支持。

## 10. 是否能记录真实谈判？

能。`transfer_negotiations` + `negotiation_events` 只追加，状态机、终态保护、事件幂等、复盘（初始报价/最终成交/差异/轮次/样本提示）均已实现；工作台可创建谈判、记录提交/反报价/完成/拒绝，并生成复盘。

边界：系统只写本地数据库，**不会向游戏提交报价**。

## 11. 是否实现存档隔离？

是。所有新表带 `fm_save_id`；球员、报价、谈判均校验归属，跨存档访问返回 404（测试 `test_offers_and_negotiations_are_save_scoped`）。AI 工具拒绝模型传入 `save_id`。

## 13. 是否存在未解决问题？

1. 数据来源缺失：历史转会、成交费用、租借/买断条款无法自动获取，这是外部扫描器能力边界。
2. 真实存档合同覆盖率为 82.8%，其余球员合同未知；未知字段在界面显式标注。
3. 真实库存在异常工资值（最大 3,413,698），已提示但不阻断报价，仍需人工判断单位。
4. 真实存档有 185 条未处理身份冲突，概览页暴露但未在本版本修复。
5. CI 只对 `main` 的 PR 触发，本堆叠 PR 的 CI 状态为 `NOT_RUN`，需要合并链路后在 main PR 上跑。
6. 估值依赖导入的已完成转会；真实存档 0 转会时所有报价都是身价基准（`confidence=low`），不能当作成交价。
