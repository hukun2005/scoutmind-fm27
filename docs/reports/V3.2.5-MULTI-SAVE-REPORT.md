# V3.2.5 多存档识别与隔离报告（Phase 7）

**自动化：既有用例覆盖；真实切换：NOT_RUN。**

## 1. 现有存档身份

- 存档身份由扫描报文的 `save_id`（`fm_save_id`）承载，导入时由服务端注入并做归属校验；
- 唯一约束与隔离：`player_instances`、`player_snapshots`、`unresolved_player_candidates`、
  `unresolved_player_observations`、`import_jobs` 都按 `fm_save_id` 分区；
- 跨存档访问返回 404（统一安全错误），客户端不能指定 `save_id` 写入其他存档。

## 2. 既有自动化覆盖

| 用例 | 位置 |
| --- | --- |
| 同一 scan 跨两个存档导入互不覆盖 | `backend/tests/test_p1_security.py` |
| Unresolved 候选/观察按存档隔离 | `backend/tests/test_unresolved_*` |
| ImportJob 列表按 owner/save 过滤 | `backend/tests/test_import_jobs_api.py` |

**限制**：`save_id` 目前来自扫描报文（读取器在存档上下文中生成），没有存档文件指纹或游戏内部
存档 ID 的独立校验；同名不同存档、备份/复制存档尚未有专门的真实样本。

## 3. 未实现

## 4. 真实验收

当前只有一个真实存档，第二个存档无法伪造。真实双存档切换 **NOT_RUN**；
不得用两个 Mock `save_id` 冒充真实验收。

## 5. 结论

程序级隔离有自动化证据；真实多存档验收未完成，发布时必须标注限制。
