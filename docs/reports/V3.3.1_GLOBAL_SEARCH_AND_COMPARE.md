# V3.3.1 全局搜索与球员对比说明

## 1. 全局搜索

### 1.1 后端

- 文件：`backend/app/api/routes_search.py`
- 路由：`GET /api/v1/search`
- 参数：`q`（≤64）、`type`（`all|players|clubs|transfers`）、`limit`（1–20，默认 8）、`save_id`（可选）
- 数据源：
  - 球员：`latest_snapshot_subquery`，按存档过滤后匹配姓名；
  - 俱乐部：`clubs` + 最新快照按俱乐部计数；
  - 转会：`transfers`，匹配球员、转出俱乐部或转入俱乐部。
- 安全与性能：
  - 用户输入中的 `%`、`_`、`\` 全部转义，`LIKE ... ESCAPE '\'`，避免通配符导致全表匹配；
  - 每类结果硬上限 20，默认 8；
  - 空查询直接返回空分类，不访问数据表；
  - 所有查询强制 `fm_save_id`，不跨存档。
- 返回结构见 [V3.3.1_SHARED_CONTRACTS.md](../architecture/V3.3.1_SHARED_CONTRACTS.md) 第 2.1 节。

### 1.2 前端

- `src/api/search.ts`：`searchAll()`，参数与后端一一对应。
- `src/types/search.ts`：统一结果类型与 `meta` 安全读取函数（缺失返回 `null`）。
- `src/components/GlobalSearch.vue`：
  - 顶栏入口 + `Ctrl/⌘ + K`；`Esc` 关闭；
  - 输入防抖 280ms，过期响应按序号丢弃；
  - 分类页签、`↑/↓/Enter` 键盘导航、`role=tablist`/`dialog` 语义；
  - 最近搜索保存在 `localStorage`（最多 6 条），不上传；
  - 球员结果可直接「+ 对比」；
  - 存档或数据版本变化时关闭面板并清空结果。
- 结果跳转：
  - 球员 → `/players/{instance_id}`
  - 俱乐部 → `/players?club_id={id}`（球员中心读取该参数并应用筛选）
  - 转会 → `/transfers?query={player_name}`

### 1.3 错误与空状态

| 场景 | 表现 |
| --- | --- |
| 空查询 | 显示最近搜索或使用提示 |
| 无匹配 | 「没有找到结果」+ 当前关键字 |
| 请求失败 | 「搜索暂时不可用」+ 具体原因 + 重试，不清空关键字 |
| 接口未上线（404/405） | 面板显示失败与原因，不阻塞页面 |
| 快速连续输入 | 只采纳最后一次请求结果 |

## 2. 球员对比

### 2.1 数据来源

- 不新增后端接口；按已选 `instance_id` 并行请求 `GET /players/{id}`，最多 4 个。
- 每个对比项只使用真实字段：基础资料、`height_cm`、`foot`、CA/PA、属性、身价、周薪、合同、完整度。
- 为支持身高/惯用脚，本轮在 `analytics/players.py` 的详情摘要中补充 `height_cm` 与 `foot`，属于只读字段扩展。

### 2.2 选择与持久化

- `src/stores/compare.ts`：最多 4 名、最少 2 名；按存档绑定；`localStorage` 只保存实例 ID。
- 支持从球员中心表格/卡片、全局搜索、对比页选择器加入；支持移除与「替换」。
- 切换存档自动清空；`404` 表示实例不属于当前存档，自动移除并提示。
- URL 使用 `/compare?ids=12,13`，可收藏、刷新恢复。

### 2.3 雷达图规则

- 维度为属性类别（technical / mental / physical 等），值为该类非空属性的算术平均（1–20）。
- **只绘制所有已选球员都有数据的类别**；缺失类别不绘制，不补 0。
- 图下固定说明：类别均值仅用于结构对比，不代表 CA/PA，也不是综合评分。
- 少于 3 个可用维度时显示空状态，不生成伪雷达。

### 2.4 确定性摘要

只允许以下可验证结论：

- CA 最高（并列时列出全部）
- PA 最高
- 年龄最小
- 身价最高
- 合同最早到期

任一结论缺少至少 2 名球员的有效数据时不生成；不输出「更强」「更值」等评价。
