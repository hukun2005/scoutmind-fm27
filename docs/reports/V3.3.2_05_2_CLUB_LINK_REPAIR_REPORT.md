## 3. 状态分类（互不混淆）

| 状态 | 定义 | 是否计入关联率分母 |
|---|---|---|
| `LINKED` | 关联到本存档内存在的俱乐部 | 是 |
| `NO_CLUB` | 来源明确表示没有俱乐部（当前数据源无此标记，实测 0） | 否 |
| `UNRESOLVED` | 来源提供了引用，但本存档内无法验证到俱乐部 | 是 |
| `INVALID_REFERENCE` | `player_instances.club_id` 指向不存在或跨存档俱乐部 | 是 |
| `MISSING_SOURCE_FIELD` | 导入报文本次没有俱乐部字段 | 否（这不是关联失败） |

关联率公式（同时给出两个口径，避免误读）：

- `club_link_rate = LINKED / (LINKED + UNRESOLVED + INVALID_REFERENCE)`，没有可识别引用时分母为 0，返回 `null`；
- `link_rate_of_total = LINKED / 总球员数`。

健康度 `status`：`NO_DATA` / `BLOCKED_BY_SOURCE` / `DEGRADED` / `PARTIAL_SOURCE` / `OK`。

## 4. UID 统一与防误绑

- 只做安全标准化：去首尾空白（`" 12345 "` → `12345`）；**不做大小写、模糊、拼音或姓名匹配**。
- 解析顺序：本存档 `clubs.id` → 原始 `clubs.uid`；两者都不可验证则保持未解析。
- 所有查询强制 `fm_save_id` 隔离；指向其他存档的俱乐部按 `INVALID_REFERENCE` 处理，绝不跨存档绑定。
- 同名俱乐部、同名球员不会合并；`player_uid` 与 `club_uid` 全部独立判定。
- `int/string` 差异只处理可安全标准化的空白；`"12345.0"` 这类无法证明相等的值不猜测。

## 5. 安全回填规则（`app/services/club_linkage.py`）

按 `player_instances.id` 键集每批 5,000 行，每批提交；失败只回滚当前批并计入 `failed`。

1. **悬空/跨存档引用**：最新快照可验证 → 重绑到本存档俱乐部（`backfill_reference`）；不可验证 → 清空 `club_id`，不保留坏引用。
2. **空值 + 最新快照 `club_id`/`club_uid` 可验证** → 回填（`snapshot_backfill`）。
3. **空值 + 高置信阵容 CSV 归属（confidence ≥ 0.8）** → 回填（`squad_csv`）。
4. **已关联但来源未知** → 仅补来源与时间标注（`player_club_field` 或 `legacy`），不改 `club_id`。

不覆盖已有正确关系；不按姓名猜测；不删除球员/俱乐部/历史快照。
