# V3.3.2-08 在线学习性能与并发验证

日期：2026-11-27
环境：Windows 11、PowerShell 7、Python 3.13、SQLite（WAL 由应用默认配置）
说明：性能数据使用**临时数据库与合成数据集**，仅用于测量处理吞吐，不写入任何正式存档，也不作为游戏事实。

## 1. 基准方法

- 数据集：400 家俱乐部、`N` 名球员实例（每名球员一个最新快照）、`N` 笔已完成的真实形态转会（含身价、年龄、位置、来源 `fm27_live_reader`）。
- 操作：单次 `transfer_learning.process_incremental`，批量 1000，统计耗时、事件数、画像更新数、吞吐。
- 计时范围：仅学习处理；数据构造不计入。
- 临时脚本位于系统临时目录，未提交到仓库。

## 2. 结果

| 数据规模 | 耗时 | 生成事件 | 画像更新 | 重点升级 | 吞吐 |
|---|---|---|---|---|---|
| 1,000 笔 | 1.36 s | 1,000 | 1,998 | 399 | ~735 事件/s |
| 10,000 笔 | 9.16 s | 10,000 | 19,976 | 399 | ~1,091 事件/s |
| 60,000 笔 | 63.18 s | 60,000 | 119,850 | 399 | ~950 事件/s |

真实数据（246,234 条挂牌观测、0 笔转会）：首次学习 **32.85 s**，生成 7,072 个挂牌事件，0 个成交事件。

## 3. 结论

- 60k 级单轮学习约 63 秒，运行在后台任务中，带进度、心跳、检查点与取消；不会阻塞页面请求。
- 事件写入采用“指纹预检 + 批量提交 + 唯一约束兜底”，不随规模线性放大数据库往返。
- 画像更新在单轮内按俱乐部缓存统计后一次写回；活动日志单轮上限 200 条。
- 无新数据轮询：只更新监控时间，不写事件、不重建画像（测试覆盖）。

## 4. 并发与恢复

| 场景 | 结果 | 证据 |
|---|---|---|
| 同存档重复启动学习 | 复用活跃任务，不重复执行 | `background_scan.create_task` + 部分唯一索引；`tests/test_background_scan.py` |
| 事件重复写入（同批/跨轮/重启） | 唯一约束兜底，跳过重复 | `test_transfer_events_are_deduplicated`、`test_same_batch_duplicate_keys_are_skipped` |
| 处理中取消 | 已提交批次保留，状态 `PARTIAL`，游标可续跑 | `test_cancel_keeps_checkpoint_and_resume_continues` |
| 应用重启 | 任务按检查点恢复；无检查点标记 `PARTIAL` | `background_scan.recover` + `TRANSFER_LEARNING` 分支 |
| 多存档并行 | 事件/画像/会话/游标均按 `fm_save_id` 隔离 | `test_save_isolation` |
| 导入接口触发 | 导入成功才触发；触发失败不影响导入结果 | `routes_core._trigger_online_learning` |

## 5. 限制

- 基准未测量内存峰值；60k 级事件对象按批次释放，未出现内存异常。
- PostgreSQL 仅由迁移与既有 CI 覆盖；本轮性能数据来自 SQLite。
- 真实成交学习性能无法在本数据源测量（0 笔转会），标 `BLOCKED_BY_REAL_DATA`。
