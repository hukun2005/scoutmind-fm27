# V3.3.2-05 谈判记录与复盘报告

- 模块：`backend/app/services/transfer_director.py`（谈判部分）
- API：`/api/v1/transfer-director/negotiations*`
- 算法版本：`negotiation-review-1`
- 边界：**只记录用户真实发生的谈判；系统不会自动向游戏提交报价，也不会把 AI 报价写成成交事实。**

## 1. 数据模型

| 表 | 用途 |
|---|---|
| `transfer_offers` | 报价草稿（AI 生成或用户保存），`source=ai_estimate/user_confirmed` |
| `transfer_negotiations` | 一次谈判：方向、状态、轮次、初始要价、用户报价、反报价、最终费用、最终条款 |
| `negotiation_events` | 只追加的过程事件，构成完整时间线 |

所有表带 `fm_save_id`，跨存档不可见（越权 404）。

## 2. 状态机

| 事件 | 结果状态 |
|---|---|
| `draft_created` | 保持 DRAFT |
| `offer_generated` | PROPOSED |
| `offer_submitted` | SUBMITTED |
| `counter_received` | COUNTERED |
| `offer_revised` | SUBMITTED |
| `accepted` | ACCEPTED |
| `rejected` | REJECTED |
| `withdrawn` | WITHDRAWN |
| `completed` | COMPLETED |
| `cancelled` | CANCELLED |
| `note` | 不改变状态 |

终态（ACCEPTED/REJECTED/WITHDRAWN/COMPLETED/CANCELLED）之后只允许追加 `note`，其它事件返回 409，避免"已完成又被改写"。

轮次 `round_count` 只在用户侧动作（提交、修改、反报价、接受、拒绝、撤回、完成）时递增。

## 3. 幂等

- 事件幂等键：`(negotiation_id, event_type, occurred_at, amount, event_data_json)` 完全一致时不重复写入，接口返回 `duplicate=true`。
- 重复导入/重复点击不会产生两条相同记录；测试 `test_duplicate_event_is_idempotent` 固定该行为。
- 导入或手动记录同一状态时不新增状态历史（见条款报告）。

## 4. 复盘

输入：谈判事件、最终费用、初始要价、当前估值。

输出：

- `outcome`：成交 / 等待游戏内完成 / 被拒绝 / 已撤回 / 已取消 / 进行中
- `delta` 与 `delta_pct`：最终费用 − 初始报价
- `round_count`、`counter_offer`、`reject_reason`、`final_terms`
- 估值对照（low/mid/high）与置信度
- **样本提示**：当前存档已完成谈判 < 5 笔时明确输出"当前历史谈判样本不足，暂不形成可靠规律"，不假装有统计规律

## 5. AI 工具

| 工具 | 说明 |
|---|---|
| `record_negotiation_event` | 记录用户确认的事件，不提交游戏 |
| `review_negotiation` | 生成复盘 |
| `get_player_contract` / `get_transfer_clauses` / `generate_purchase_offers` / `generate_sale_offers` | 为谈判提供确定性上下文 |
| `generate_loan_offers`（V3.3.2-05.1 新增） | 生成三套租借方案 |
| `get_transfer_opportunities` / `get_transfer_strategy_cases`（V3.3.2-05.1 新增） | 雷达与成交策略上下文 |

工具入口校验 `fm_save_id` 与实体归属；模型不能传存档 ID。

## 6. 界面（`/transfer-director` → 报价工作台 → 谈判记录）

- 左侧谈判列表（状态标签），右侧详情 + 事件时间线。
- 事件表单支持金额与备注；完全相同事件提示"未重复写入"。
- 一键生成复盘，展示结果、轮次、初始报价、最终成交、差异与样本提示。
- 买入/出售/租借方案卡片可直接"记录谈判"，自动带入报价金额作为初始要价。

# V3.3.2-05.1 扩展：租借谈判与案例闭环

- 状态：**PASS**（记录、状态机、幂等、复盘、租借方向）；真实样本归纳 **BLOCKED_BY_SOURCE**
- 本轮新增内容向上文完全兼容，未修改既有状态机与幂等规则。

## 9. 本轮变化

- 谈判方向新增 `loan`：API `CreateNegotiationRequest.direction`、服务层、前端类型与按钮同步；买卖租借共用同一状态机。
- 租借方案卡片支持"保存草稿"与"记录谈判"，初始要价自动取 `total_committed`（租借费）。
- `COMPLETED` 的谈判进入成交策略案例（`case_origin=negotiation`），下一次相似匹配与规则归纳可见，形成"报价 → 谈判 → 复盘 → 案例"闭环。
