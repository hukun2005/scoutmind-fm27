## 2. A. 查询性能

详见 [V3.3.2_PERFORMANCE.md](file:///C:/Users/hukun/Desktop/FM27-v331n/docs/reports/V3.3.2_PERFORMANCE.md)。

- 新增 `player_instances.latest_snapshot_id`（migration `b8f3d2a6c1e9`）；真实副本回填 112,686 个实例，0 个有快照但空引用。
- 最新快照读取采用「主键 JOIN + 空引用回退」，旧库与直接写入的测试数据行为不变。
- 新增索引：`player_instances(fm_save_id, club_id)`、`(fm_save_id, position)`、`watchlist_items(player_instance_id)`、`transfer_history(fm_save_id, player_name)`。

## 3. B. 全局搜索

- `GET /api/v1/search` 固定返回 `players / clubs / transfers / watchlist` 四类；空查询不扫描数据表。
- 球员：姓名 + 位置代码 + 当前俱乐部名称；俱乐部：名称 + 国家 + 联赛；转会：球员/买卖方 + 类型 + 状态 + 日期；关注：球员 + 名单 + 状态 + 标签 + 备注。
- LIKE 通配符按字面量转义；所有分类按服务端注入/校验的 `save_id` 隔离；同名球员用 `instance_id` 区分。
- 前端 Ctrl+K、↑/↓、Enter、Esc、280 ms 防抖、请求序号丢弃过期响应；结果命中高亮（先转义 HTML）；最近搜索与最近访问只存本地、按存档隔离。
- 旧版 3 类响应仍兼容：缺少 `watchlist` 字段不会导致前端报错（`?? []`）。

## 4. C. AI 足球总监

- 页面 `/director`：左侧俱乐部/存档/完整度/缺口，中间问题与结构化分析，右侧推荐与球员卡片。
- 六类意图：阵容补强、球员培养、出售/外租、引援计划、关注名单、年龄结构；其他问题回退到既有 AI 球探助手。
- 回答结构：`conclusion` / `sections[]`（fact / computed / inference / unavailable）/ `recommendations[]` / `player_cards[]` / `data_gaps[]` / `citations[]` / `mode`。
- 复用 `squad_overview`、`candidate_pool` + 六维评分、`watchlist`、`roster`；没有复制评分规则。
- 请求体拒绝 `save_id`（422）；查询参数 `save_id` 必须属于当前用户；每次请求按该存档重新取数。
- 无 LLM 时 `mode=deterministic-rules`，不宣称离线大模型能力；不自动修改球员/关注/转会状态。

## 6. 已知限制

- 无筛选的全池引援推荐在 6.2 万人存档仍需约 19.5 秒（六维评分遍历全池）；界面与 AI 总监按位置过滤，实际为约 4 秒或缓存命中。
- 缓存为单进程内存缓存；多进程部署只影响命中率，不影响正确性。
- AI 总监是确定性规则编排，不是大模型推理；建议质量受 CA/PA/合同/统计完整度限制。
- 未引入 FTS5；当前 `LIKE` 搜索在真实数据上 118–201 ms 满足需求，后续数据量显著增长时再评估。
- 数据模型没有球员/俱乐部别名或昵称字段；搜索按姓名、位置代码、俱乐部名、国家与联赛匹配，不臆造别名。
- 真实存档本身没有转会与统计，相关模块通过既有空态与 `data_gaps` 呈现，未伪造。
