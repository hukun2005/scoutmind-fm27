# V3.2.9 测试方案（准备阶段）

实现尚未开始（前置条件未满足），本文件只定义"合并后必须通过"的用例，当前状态均为 `NOT_RUN`。

## 1. UID

| 用例 | 期望 |
| --- | --- |
| 同存档唯一 UID | `Valid` |
| 同存档重复 UID | `Duplicate`，不自动合并，全部保留 |
| 不同存档相同 UID | 不认定同一球员 |
| 缺失 UID / Sentinel UID | `Missing`，不默认为 0 |
| UID 变化 / 版本变化 / 布局变化 | 重新评估，不复用旧观测 |
| 重复导入 / 断点恢复 | 幂等，不产生重复行 |

## 2. Person 关联

| 用例 | 期望 |
| --- | --- |
| 一对一 / 一对多 / 多对一 | 有明确状态与证据 |
| 无匹配 | `NoMatch`，不猜测 |
| 同名冲突 / 生日冲突 | `Conflicted`，保留双方 |
| 俱乐部变化 | 不影响身份 |
| Unicode / 重音姓名 | 规范化后可比较，不误合并 |
| 属性记录缺失 / Person 指针失效 | 重新读取，不复用旧指针 |

## 3. 跨存档

| 用例 | 期望 |
| --- | --- |
| A → B / B → A / A → B → A | 存档隔离，历史保留 |
| 同一球员不同 UID | 候选，不自动合并 |
| 不同球员相同 UID | 不合并 |
| 存档删除/重新加载 | 历史身份保留，重新关联 |

## 4. 历史转会

正常转会、租借、自由转会、附加条款、取消/未完成、同一球员多次转会、转会前后身份持续、
冲突交易进入待审核。

## 5. 并发与恢复

两个扫描并发、相同 scan_id 重复执行、同批次重复提交、扫描中断、服务重启、存档切换、
用户取消、断点恢复、并发人工审核；均不得产生重复身份或重复转会记录。

## 6. 迁移与兼容

SQLite upgrade / downgrade / 再 upgrade；PostgreSQL 兼容；索引与唯一约束；历史数据兼容。

- Stale 身份不得被批处理"洗白"为 Verified。
- 跨存档缓存必须绑定 Save Identity / Session / Build / Layout。
