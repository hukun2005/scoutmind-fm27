# ScoutMind V3.3.3-01 架构设计（Phase 1）

- 基线：`main @ 5edc1ba`；分支 `feature/v3.3.3-01-langgraph-runtime`
- 依赖审计：`docs/v333/V3.3.3-01-REPOSITORY-AUDIT.md`

## 1. 目标架构

```
Frontend (Vue3)
  AgentView: 任务输入 / 进度 / 确认卡片 / 报告 / 历史 / 断线恢复
        │ HTTP + SSE
FastAPI routes_agent.py（既有端点 + 新增 /agent/tasks*）
        │
AgentRuntime（app/agent_runtime/runtime.py，唯一入口）
  ├─ AgentGraph（LangGraph StateGraph）
  ├─ State（类型化 AgentTaskState）
  ├─ ModelProvider（OpenAI 兼容 / 规则回退 / 测试 Mock）
  ├─ ToolAdapter（包装 llm_planner.TOOL_SPECS + tools.py，不重写业务）
  ├─ ApprovalService（一次性确认、过期、幂等）
  ├─ Checkpointer（SQLite 优先 / PG 兼容 / 内存仅测试）
  └─ EventBus（业务库事件表 + 内存环形缓冲，SSE 由游标重放）
        │
业务真相：agents/service.py answer_question()、agents/tools.py、analytics/*、services/*
```

原则：Runtime 只做编排；数字与结论仍来自确定性工具；模型不接触 `save_id / user_id / thread_id`。

## 3. State 设计（`state.py`）

```python
class AgentTaskState(TypedDict, total=False):
    # 身份（服务端注入，模型不可写）
    task_id: str
    thread_id: str
    user_id: int
    save_id: int
    save_generation: int | None
    # 任务
    task_type: str
    user_goal: str
    execution_plan: list[dict]
    current_step: str
    completed_steps: list[str]
    pending_steps: list[str]
    tool_results: list[dict]
    analysis_results: dict
    approval_requests: list[dict]
    approved_actions: list[dict]
    execution_status: str   # queued/running/waiting_approval/paused/completed/failed/cancelled
    error: dict | None
    final_report: dict | None
    # 控制
    step_count: int
    tool_call_count: int
    created_at: str
    updated_at: str
```

安全约束：`save_id` 等在服务端写入；每步工具调用前重校验实体归属；State 不写入 API Key、原始存档、Traceback。

## 4. Graph 设计（`graph.py` + `nodes.py` + `edges.py`）

节点：

| 节点 | 职责 |
| --- | --- |
| `validate_scope` | 校验用户、存档归属、存档代次、任务类型 |
| `classify` | 规则分类任务（复用 `planner.parse` / `director.classify`） |
| `plan` | 生成计划：模型 Provider 或规则模板；计划项 = `{tool, arguments, reason}` |
| `validate_plan` | 复用 `llm_planner.parse_plan` 的严格校验 + 步数/工具数上限 |
| `execute_step` | 通过 `ToolAdapter` 执行一个工具；记录事件与结果 |
| `review_results` | 判定：继续 / 需要确认 / 生成报告 / 失败 |
| `request_approval` | `interrupt()` 挂起，写 approval 记录 |
| `apply_approved` | 校验 approval 一次性 + 载荷哈希 + 代次，执行副作用 |
| `finalize_report` | 复用 `service`/`director` 组装报告结构，写业务库 |
| `fail` | 结构化错误（分类 + 用户可读原因） |

条件边：

```
START → validate_scope → classify → plan → validate_plan → execute_step
execute_step → review_results
review_results ─┬─ continue ───────────→ plan（补充分析，受 max_steps 限制）
                ├─ approval_required ──→ request_approval → (resume) apply_approved → review_results
                ├─ report_ready ───────→ finalize_report → END
                └─ failed ─────────────→ fail → END
```

硬限制（`settings`）：`agent_max_steps=8`、`agent_max_tool_calls=5`、`agent_task_timeout_seconds=120`、`agent_model_timeout_seconds=30`、`agent_tool_timeout_seconds=10`、`agent_max_concurrent_tasks=2`、`agent_event_buffer=200`、`agent_approval_ttl_seconds=600`。

## 5. Provider 设计（`model_provider.py`）

```python
class ModelProvider(Protocol):
    provider_id: str
    supports_tool_calling: bool
    supports_streaming: bool
    def plan(self, *, messages: list[dict], tools: list[dict], timeout: float) -> ModelReply: ...
```

- `OpenAICompatibleProvider`：`base_url + /v1/chat/completions`，`response_format=json_object`，温度 0；保留现有 DeepSeek 配置键，新增 `agent_llm_provider_id`（默认 `openai-compatible`）。
- `RuleProvider`：无 Key / 关闭 LLM 时的确定性回退（不伪装成 AI）。
- `MockProvider`：仅测试使用，生产入口硬拒绝。
- 真实 GLM-4.7-Flash 验证：无 Key 时 `REAL_PROVIDER_ACCEPTANCE=NOT_RUN`，不伪造。
- API Key 只从环境/本地配置读取，不进 State、不进日志、不返回前端。

## 6. Checkpointer 设计（`checkpointer.py`）

| 环境 | 实现 | 说明 |
| --- | --- | --- |
| 默认 SQLite | `SqliteSaver`（独立 `data/agent_checkpoints.db`，WAL） | 与业务库分离，避免主库锁竞争 |
| PostgreSQL | `AsyncPostgresSaver`（可选依赖） | 缺失时明确 `CHECKPOINT_UNSUPPORTED`，不静默降级 |
| 测试 | `InMemorySaver` | 仅单元测试 |
| 应用重启 | 启动扫描 `agent_tasks` 中 `running/waiting_approval/paused` → 校验 checkpoint 存在 → 恢复或标记 `failed(resumable=false)` |
| 清理 | `agent_checkpoint_retention_days=7`，定时删除已完成任务的 checkpoint | 不删除业务审计 |

并发：单任务串行；多任务之间不共享 SQLite 连接；写入由 runtime 串行化（`asyncio.Lock` 或线程锁）。

## 7. 数据库迁移（新增，不修改历史）

新增表：

- `agent_tasks`：`id`(uuid, pk)、`conversation_id`、`user_id`、`fm_save_id`、`save_generation`、`task_type`、`user_goal`、`status`、`progress`、`current_step`、`final_result`(JSON)、`error_code`、`error_summary`、`provider_id`、`model_id`、`step_count`、`tool_call_count`、`created_at`、`updated_at`、`started_at`、`finished_at`。索引：`(fm_save_id, created_at)`、`(status)`。
- `agent_task_events`：`id`(自增)、`task_id`(FK)、`seq`（任务内递增）、`event_type`、`payload`(JSON)、`created_at`；唯一约束 `(task_id, seq)`。
- `agent_approvals`：`id`(uuid)、`task_id`、`approval_type`、`operation_type`、`payload`(JSON)、`payload_hash`、`reason`、`status`、`user_id`、`fm_save_id`、`save_generation`、`expires_at`、`created_at`、`decided_at`、`consumed_at`；唯一约束 `(task_id, payload_hash, status)` 防重复挂起。

迁移要求：SQLite 升级/降级/再升级；PostgreSQL 16 CI；不 `downgrade base` 真实库。

## 8. API 设计

复用既有 `/agent/conversations*`、`/agent/director/*`，新增：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/agent/tasks` | 创建任务（goal、task_type?、conversation_id?） |
| GET | `/api/v1/agent/tasks` | 当前存档任务列表（分页/状态筛选） |
| GET | `/api/v1/agent/tasks/{task_id}` | 任务详情（状态、进度、报告、错误、待确认数） |
| GET | `/api/v1/agent/tasks/{task_id}/events?after=` | 事件列表（游标重放） |
| GET | `/api/v1/agent/tasks/{task_id}/events/stream` | SSE 事件流（Last-Event-ID 重放 + 心跳） |
| POST | `/api/v1/agent/tasks/{task_id}/cancel` | 取消（幂等） |
| GET | `/api/v1/agent/tasks/{task_id}/approvals` | 待确认操作 |
| POST | `/api/v1/agent/tasks/{task_id}/approvals/{approval_id}/approve` | 确认并恢复 Graph |
| POST | `/api/v1/agent/tasks/{task_id}/approvals/{approval_id}/reject` | 拒绝并安全结束/回退 |
| POST | `/api/v1/agent/tasks/{task_id}/resume` | 恢复暂停任务 |

安全：全部依赖 `get_active_save` + `get_current_user`；任务不属于当前存档 → 404/403 安全错误；approve 时重校验用户、存档、`save_generation`、`payload_hash`、`expires_at`。

事件类型：`task_created/started/plan_created/step_started/tool_started/tool_completed/analysis_updated/approval_required/task_paused/task_resumed/task_completed/task_failed/task_cancelled`；`safe_payload` 不含 Key、原始存档、Traceback。

## 9. 前端设计（复用 V4.0 页面）

`AgentView.vue` 增加（不重做首页）：

1. 任务输入：自然语言 + 可选任务类型；创建后显示「当前任务」。
2. 进度：步骤时间线（用户语义：正在查看阵容 / 正在比对球员 / 正在整理报告），不显示 Node/Checkpoint。
3. 确认卡片：操作、原因、影响、确认/拒绝/查看详情；过期显示「已失效」。
4. 报告：沿用现有结论/依据/风险/球员卡。
5. 恢复：刷新后按任务快照与事件游标恢复；断线重连。
6. 历史任务列表（当前存档）。
7. 高级诊断（折叠）：provider、耗时、工具调用数、错误码。

轮询为主、SSE 可选（若 SSE 在前端复杂度不可控，则先用 3s 轮询 + `after` 游标，SSE 端点仍保留）。

## 10. 兼容与回退

- 旧 `/agent/conversations` 端点与规则路径完全保留；前端旧对话流可用。
- LLM 关闭 / 无 Key / Provider 失败 → 任务仍可执行，报告标注 `mode=deterministic` 与回退原因。
- LangGraph 导入失败（打包缺失）→ Runtime 启动时 `RUNTIME_UNAVAILABLE`，旧 Agent 仍可用；不允许静默吞掉。
