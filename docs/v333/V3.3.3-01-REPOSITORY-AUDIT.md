## 2. 当前架构（as-is）

```
Vue3 (frontend)
  AgentView / DirectorView / TransferDirectorView
        │  HTTP JSON
        ▼
FastAPI (backend/app/api/routes_agent.py)
  GET/POST /agent/conversations
  GET/POST /agent/conversations/{id}/messages
  GET  /agent/director/context
  POST /agent/director/ask
  GET  /agent/reports
        │
        ▼
agents/service.py  answer_question()
  ├─ planner.py            规则意图解析（Intent）
  ├─ llm_planner.py        可选 LLM 规划（OpenAI 兼容 JSON）
  ├─ director.py           规则版 AI 足球总监（分类 + 模板化回答）
  └─ tools.py              31 个确定性业务工具（ToolCall）
        │
        ▼
analytics/* / services/* / SQLAlchemy → SQLite / PostgreSQL
```

- 全部结论与数字来自确定性工具；LLM 只做「选工具 + 组织说明」。
- 配置 `backend/app/config.py`：`agent_llm_enabled`（默认 false）、`agent_llm_base_url`（默认 DeepSeek）、`agent_llm_model`、`agent_llm_api_key`、超时/重试/单价。
- 当前无任何 `langgraph` / `langchain` 代码或依赖（全仓库 grep 为空）。

## 3. 现有 Agent 执行流程（代码依据）

1. 用户提问 → `POST /agent/conversations/{id}/messages`（`AskRequest`）。
2. 路由用 `get_active_save` 注入存档、`get_current_user` 注入用户；`body.save_id` 必须等于会话存档，否则 400 `save_mismatch`。
3. `agent_service.answer_question(session, save_id, question, instance_id, club_id, user_id)`：
   - 传 `user_id` 时先校验 `FmSave.user_id` 归属。
   - `planner.parse()` 生成规则意图（squad/depth/recruitment/growth/compare/valuation/similar/club_profile/deal/price_stats/transfer_history）。
   - 若 `llm_planner.llm_enabled()`：`plan_with_llm()` 一次调用模型拿 JSON 计划 → `parse_plan()` 严格校验 → `execute_plan()` 顺序执行；
     任一 `LlmUnavailable` / `PlannerError` 都降级到规则路径，并在回答写 `llm_fallback` 原因。
   - 规则路径按 intent 调用对应组装函数，追加 `evidence`、`reliability`、`citations`、`player_cards`。
4. 路由把用户消息、助手消息（`answer_json`、`tool_calls_json`）与 `AiReport` 落库。

**关键限制（相对任务书）**

| 任务书要求 | 现状 |
| --- | --- |
| 多轮推理 / 条件分支 | 不支持：一次模型计划 = 最多 5 个工具，顺序执行后结束 |
| 任务暂停/恢复 | 不支持 |
| Human-in-the-loop 确认 | 不支持（无 interrupt / approval） |
| 任务状态持久化 | 不支持：只有对话消息，没有 task 记录 |
| 应用重启恢复 | 不支持 |
| 事件流 | 不支持（同步 JSON 响应） |
| Checkpoint | 不支持 |

## 4. 业务工具清单

- `tools.py`：`TOOL_NAMES` 共 **31** 个确定性工具（含报价、关注、谈判、机会雷达等）。
- `llm_planner.py`：`TOOL_SPECS` 共 **27** 个暴露给模型的工具（名称与参数 schema 严格声明；未暴露 4 个内部工具）。
- 工具返回统一 `ToolCall(name, arguments, result, summary)`，`payload()` 为唯一对外结构。

参数与作用域校验：

- `_validate_arguments()`：类型、bool 不得冒充 integer/number、NaN/Infinity 拒绝、枚举、min/max、minLength/maxLength、required、未知键拒绝。
- `FORBIDDEN_ARGUMENTS = {save_id, fm_save_id, user_id, session_id}`：模型一旦提供直接报错。
- `_assert_tool_scope()`：`instance_id / transfer_id / club_id / shortlist_id / candidate_id` 调用前校验属于当前 `save_id`，错误不泄露记录是否存在。
- `save_id` 全程由服务端注入，模型不可见、不可改。
- 最大工具调用：`MAX_TOOL_CALLS = 5`。

## 9. LangGraph 集成方案（摘要）

- 目录：`backend/app/agent_runtime/`；`StateGraph` 主图 + `state.py` 类型化 State + `checkpointer.py`（SQLite 优先，PG 兼容）。
- Runtime 统一入口：`create_task / execute / stream / get / pause / resume / cancel / recover_pending / list`。
- 双层持久化：业务库 `agent_tasks/agent_approvals/agent_task_events`（新增迁移）；LangGraph checkpoint 独立表。
- 工具复用：`tool_adapter.py` 包装现有 `llm_planner.TOOL_SPECS` 与 `tools.py`，不重写业务逻辑。
- HITL：`interrupt()` + `Command(resume=...)`；approval 绑定 `task_id/approval_id/user_id/save_id/generation/payload_hash/expires_at`，一次性消费。
- 兼容：`routes_agent.py` 保留现有端点；新增 `/agent/tasks*`；LLM 不可用时退回规则路径。
