# ScoutMind V3.3.3-01 测试方案（Phase 1）

- 设计原则：先测试后实现；不删除既有测试、不降低断言；Mock Provider 只用于单元测试，真实 Provider 无 Key 时 `NOT_RUN`。
- 基线：后端全量 pytest（最近 main CI 绿）、前端 65 passed、.NET CI 绿。

## 1. 测试分层

| 层 | 位置 | 目的 |

| L1 Runtime 单元 | `backend/tests/test_v333_runtime_*.py` | Graph/State/边/上限/错误 |
| L2 工具适配 | `backend/tests/test_v333_tool_adapter.py` | 27 工具映射、参数、作用域、幂等 |

| L8 回归 | 既有全部 | 不退化 |

## 2. L1 Runtime 单元

1. Graph 创建成功；`compile()` 无异常。
2. State 初始注入 `user_id/save_id/thread_id`，模型不可改写（尝试写入被拒）。
3. `validate_scope`：存档不存在 / 不属于用户 / generation 不匹配 → 安全错误。
4. `classify`：任务类型识别（squad/player/compare/recruitment/transfer/valuation/watchlist/director）。
5. `plan` + `validate_plan`：未知工具、越界参数、超 5 个工具 → 计划被拒。
6. 多步循环：达到 `max_steps` 强制结束并标记 `failed(STEP_LIMIT)`。
7. 工具连续失败：达到上限后进入 `fail`，不无限重试。
8. 条件边：`report_ready` 走 `finalize_report`；`approval_required` 走中断。
9. 事件序列：`task_started → plan_created → step_started → tool_completed → task_completed` 单调递增。
10. 超时：模型超时、工具超时、任务总超时分别映射错误码。

## 3. L2 ToolAdapter

1. `TOOL_SPECS` 27 个全部可通过 Adapter 调用（用临时 SQLite 夹具）。
2. 参数校验：bool 冒充 integer、`NaN`、未知键、超长字符串、枚举越界全部拒绝。
3. 作用域：`instance_id/transfer_id/club_id/shortlist_id/candidate_id` 跨存档 → 统一安全错误，不泄露存在性。
4. `save_id/user_id/session_id/fm_save_id` 出现在模型参数 → 直接拒绝。
5. 只读工具无副作用（调用前后业务表行数不变）。
6. 副作用工具（关注名单）幂等：同任务同 payload 重复执行只写一次。
7. 报价工具：金额来自确定性引擎，Adapter 返回值与既有 `tools.py` 完全一致（快照对比）。
8. 工具执行异常：返回结构化 `TOOL_EXECUTION` 错误，不中断整个 Graph（除非连续失败超限）。

## 4. L3 Human-in-the-loop

1. 正常任务无确认：直接完成，approval 表为空。
2. 需要确认：Graph `interrupt`，任务状态 `waiting_approval`，事件含 `approval_required`。
3. 确认：恢复执行，副作用仅执行一次（计数 = 1）。
4. 拒绝：任务状态 `cancelled`，无副作用。
5. 过期：超过 TTL 后 approve → `APPROVAL_EXPIRED`，无副作用。
6. 重复确认：第二次 approve → `APPROVAL_CONSUMED`，无副作用。
7. 拒绝后批准：`APPROVAL_REJECTED`，不可恢复为批准。
8. 存档切换：切到 B 后 approve A 的确认 → `SAVE_MISMATCH`；切回 A 且 generation 未变才可继续。
9. 跨用户：用户 B 无法 approve A 的任务（404/403）。
10. 载荷篡改：payload 哈希不一致 → 拒绝执行。
11. 重启后恢复：进程重启后 approve 仍可恢复 Graph（checkpoint 存在）。
12. 幂等重放：resume 端点重复调用不重复执行副作用。

## 5. L4 Checkpoint / 恢复

1. SQLite Checkpointer 保存/读取 thread 状态。
2. 进程重启：运行中任务 → 启动扫描 → `recover_pending_tasks` 恢复或标记不可恢复。
3. 多任务隔离：两个 thread 状态互不覆盖。
4. 并发写入：两个任务同时 checkpoint 不出现 `database is locked`（重试 + 串行写）。
5. 业务任务状态与 checkpoint 不一致：标记 `RESUME_FAILED`，不伪装成功。
6. 清理策略：过期 checkpoint 删除，业务审计保留。
7. PostgreSQL：CI `postgres-migrations` job 中执行同套 checkpoint 用例；本地无 PG 标记 `NOT_RUN`。

## 6. L5 API

1. 创建任务：201，返回 `task_id/status`；绑定当前存档与用户。
2. 列表：仅返回当前存档任务；跨存档不可见。
3. 详情：状态、进度、报告、错误、待确认数；不含内部 State/Key。
4. 事件：`after` 游标重放；事件 `seq` 单调；`safe_payload` 无敏感字段。
5. SSE：`text/event-stream`，`Last-Event-ID` 重放，心跳；连接断开不影响任务。
6. 取消：`queued/running/waiting_approval` 可取消；已完成任务取消 → 幂等成功或 409。
7. approve/reject 端点权限与状态机测试（同 L3）。
8. 兼容：旧 `/agent/conversations/*` 与 `/agent/director/*` 行为不变（既有测试全绿）。

## 7. L6 迁移

1. SQLite：`upgrade head` → `downgrade -1` → `upgrade head`。
2. 新表索引/唯一约束存在性断言。
3. 旧数据兼容：既有 `agent_conversations/agent_messages/ai_reports` 可读写。
4. PostgreSQL 16：CI job 执行相同迁移。
5. 迁移安全检查脚本 `scripts/check_migration_safety.py` 通过。

## 8. L7 前端 E2E（Playwright，mock API）

1. 创建任务 → 显示当前任务与进度步骤。
2. 进度事件推进（step_started/tool_completed）→ UI 更新。
3. 出现确认卡片 → 显示操作/原因/影响；点击确认 → 任务继续至完成。
4. 点击拒绝 → 任务安全结束，不显示成功。
5. 刷新页面 → 按任务快照恢复状态。
6. 事件游标断线重连 → 不重复/不丢步骤。
7. 存档切换 → 旧任务列表不显示，旧任务提示失效。
8. 高级诊断折叠：默认不显示 Node/Checkpoint/技术参数。
9. 既有 65 条用例全部通过。

## 10. 测试夹具与隔离

- 每用例独立临时 SQLite（`tmp_path`），复用 `backend/tests/conftest.py` 的 `db`/`client` 夹具。
- 任务必须携带测试用户与测试存档；跨存档用例显式创建两个 `FmSave`。
- 时间相关（TTL/超时）使用可注入时钟或极短 TTL，不 sleep 长等待。
- 不依赖网络；Provider 用 Mock 只在 L1/L2/L3 使用，L7 通过前端 mock。
