# V3.3.3-02 性能基线（BASELINE）

## 1. 结论

在改造前的代码（`feature/v3.3.3-02-performance-optimization` 基线 `f6017f7`）上，用固定分布数据集
测得三档规模基线。核心结论：

1. **转会列表的位置筛选在 5 万行级别直接报错**：`OperationalError: too many SQL variables`。
   现有实现把整张转会表加载成 ORM 对象后，再用实例 ID 列表做 `IN` 查询，超过 SQLite 绑定变量上限。
2. **转会「联赛 + 位置」组合筛选是最大热点**：10k 规模 755 ms，100k 规模 2140 ms，500k 规模 2344 ms，
   且 SQL 条数随页数增长（69 → 129）。
3. **球员详情 5 连查随存档规模线性变慢**：10k 40.5 ms → 100k 191 ms，因为每次详情都加载全存档俱乐部。
4. **Agent 事件写入每条约 3 ms**：50 条事件 150 ms、100 条 SQL（50 次 `MAX(seq)` + 50 次 INSERT），
   每个工具步骤 3~4 次 commit。
5. 导入吞吐约 **176 人/秒**（5000 人 28.4 s），在本阶段未改动。
