# ScoutMind FM27 V3.2.6 日期定位报告

## 1. 本轮实现

新增 `world-date` 命令（`WorldDateResolver`）：

```text
WorldDateLocator 签名扫描（日期 + 参考日期 + 0xFFFFFFFF + 两个 0）
    → 过滤：日期 2000..2060、参考日期晚于当前、间隔 30..400 天
    → 取日期最新的一条
    → 同一天多条 → ambiguous
    → 对选中字段连续读 3 次，值不一致 → unstable
    → 输出 date + confidence=heuristic
```

CLI：

```text
ScoutMind.LiveReader.exe world-date [--max-mb <1..8192>] [--json]
```

输出字段：`date`、`confidence`（只有 `heuristic`，不会自称 verified）、`candidate_count`、
`total_matches`、`reason`、`candidates[*]`（字段地址、原始值、参考日、间隔天数）。

无进程时返回 `game_not_running`、退出码 2（已实测）。

## 2. 为什么是“启发式”而不是“已验证”

- 签名在真实存档里有 142 条命中，单靠结构无法唯一确定；
- “最新日期”规则在当前样本里选中了正确记录，但**未来日期的事件记录**也可能共享该结构；
- 因此只标注 `heuristic`，自动快照不得使用它。

## 3. 真实历史证据（本分支之前）

| 时刻 | 界面 | 内存（同一结构） | 结果 |
| --- | --- | --- | --- |
| 10-26 | 10-26 | `0x07EA012B` | 一致 |
| 10-31 | 10-31 | `0x07EA0130` | 一致 |
| 11-06 | 11-06 | `0x07EA0136` | 一致 |
| 重启后 | 11-06 | 新地址同结构 = 11-06 | 一致 |

“0 点少读一天”的旧观察已证伪：当时读的是赛程日历对象（固定 10-25），不是时钟。
