# ScoutMind FM27 V3.2.2.4 — OBJ_DUNI 诊断

- 分支：`codex/v3.2.2.3-date-discovery`（V3.2.2.4 工作分支）
- 真实 FM27：pid 105040，build 26620374，plugin 27.1
- 日期：2026-11-23

## 1. 修复内容

`ProbeIntegrity` 现在：

1. 先按对象地址去重；
2. 区分 DB 不可读、UID 读取失败、UID=0、UID=0xFFFFFFFF 哨兵、合法 UID；
3. 唯一性比例只用“成功读取且合法”的 UID 计算；
4. 新增 `ObjectIdDiagnostics` 与 `ObjectIdSample`，失败不再进入重复分母。

## 2. 真实探测结果

真实 `probe --json`：

```text
探测 integrity 失败：UID 合法比例（0=0，哨兵=14）：57/71（80%，阈值 95%）
```

拆解：

| 指标 | 值 |
| --- | --- |
| 候选对象 | 71 |
| 去重对象 | 71 |
| 重复对象地址 | 0 |
| 可读 UID | 71 |
| 合法 UID | 57 |
| 零 UID | 0 |
| 哨兵 UID（0xFFFFFFFF） | 14 |
| 重复合法 UID | 0 |
| 不可读 UID | 0 |

结论：

- 不再把读取失败/重复对象误判为重复 UID；
- 57 个合法 UID **全部唯一**（重复 UID=0）；
- 失败原因是 14 个对象 UID 为 `0xFFFFFFFF`，合法覆盖率 80% < 95%；
- 这不是唯一性冲突，也不能通过降低 95% 阈值解决。

## 3. 解释与限制

14 个哨兵对象可能是：

- 非球员对象被 vtable 误分类；
- 未分配 UID 的临时/青年对象；
- `OBJ_DUNI` 偏移对部分对象类型不适用；
- 男子/女子数据库或不同对象子类型差异。

当前没有独立证据证明是哪一种，因此不能：

- 降低阈值；
- 把哨兵 UID 当合法；
- 把哨兵对象从分母静默删除；
- 修改 `OBJ_DUNI` 偏移。
