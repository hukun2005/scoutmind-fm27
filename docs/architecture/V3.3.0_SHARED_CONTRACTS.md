# ScoutMind FM27 V3.3.0 — 共享契约（UI 工作流 × 数据引擎工作流）

本文件是两个并行工作流唯一的事实来源。若后端实现与本文件不一致，以 `backend/app/api/routes_datahub.py` 与 `backend/app/datahub/**` 为准，并由数据引擎工作流更新本文件。

## 1. 文件所有权

| 范围 | 负责工作流 | 说明 |
| --- | --- | --- |
| `backend/app/datahub/**`、`backend/app/api/routes_datahub.py` | A：数据引擎 | 识别、校验、修复、去重、事务导入 |
| `backend/alembic/versions/**`、`backend/app/models.py` | A | 数据库迁移与模型 |
| `backend/tests/test_datahub_*.py` | A | 引擎测试 |
| `README.md`、`CHANGELOG.md`、`docs/ROADMAP.md`、`docs/API.md` | A | 版本与接口文档 |
| `frontend/src/api/datahub.ts`、`frontend/src/types/datahub.ts` | B：UI/UX | 仅封装契约，不假设额外字段 |

| 其他 `frontend/src/**` | B | 页面、组件、样式、前端测试 |
| `frontend/tests/e2e/**` | B | Playwright |

规则：同一文件同一时间只有一个负责人；需要跨界修改时先在本文件登记，再动手。

## 2. 数据中心接口

```jsonc
{
  "game": {
    "running": true, "detected": true, "pid": 4242,
    "version": "27.1.0.26620374", "exe_path": "...",
    "message": null,
    "compatibility": "supported",           // supported | unknown | unsupported
    "compatibility_message": ""
  },
  "save": {
    "id": 1, "name": "存档名", "recognized": true,
    "identity_status": "verified", "can_sync": true, "message": ""
  },
  "records": { "players": 120, "clubs": 18, "transfers": 12, "snapshots": 40 },
  "last_sync": {
    "job_id": 7, "status": "succeeded", "source": "fm27_live_reader",
    "received_at": "...", "finished_at": "...", "players": 120, "transfers": 12
  },
  "health": { "status": "ok", "issues": [] },   // ok | attention | empty

    "unresolved_players": 0, "identity_conflicts": 0,
    "quarantined_rows": 0, "total": 0
```

UI 用途：首页欢迎区连接状态、系统设置「游戏连接 / 记录数」、数据中心状态卡。`health.status` 与 `needs_confirmation.total` 直接展示，不由前端推断。

### 2.2 `POST /api/v1/data-hub/import`

- 请求：`multipart/form-data`，字段名 `file`；查询参数 `dry_run`（可选）、`filename`、`operation_id`、`save_id`。
- 响应（`DataHubImportResponse`）：

```jsonc
{
  "status": "PASS",                       // PASS | PARTIAL | FAIL | ROLLED_BACK | BLOCKED
  "stages": [{ "id": "detect", "label": "正在识别数据", "status": "pass" }],
  "detection": {
    "source": "scan_json",                // scan_json | scan_ndjson | fmscout_dump | squad_csv | unknown
    "format": "json", "schema_version": "1.0",
    "encoding": "utf-8-sig", "compatible": true,
    "code": null, "message": null, "warnings": []
  },
  "counts": { "created": 0, "updated": 120, "duplicates": 0, "repaired": 3, "quarantined": 0, "rejected": 0 },
  "import": { "dry_run": false, "job_id": 8, "save_id": 1, "scan_id": "...", "duplicate": false },
  "verification": { "status": "PASS", "checks": [] },   // PASS | PARTIAL | FAIL（大写）
  "warnings": [],
  "repairs": [{ "entity": "player", "row": 42, "rule": "l1.numeric_string", "field": "ca", "before": "148", "after": 148, "level": 1, "reason": "数字字符串转数字" }],
  "repairs_total": 3,
  "quarantine": [{ "row": 7, "entity": "player", "code": "missing_name", "message": "缺少姓名" }],
  "quarantine_total": 1
}
```

实际阶段与顺序（6 步，`stages[]` 与之一致）：
`detect 识别 → check 检查 → match 匹配 → repair 修复 → import 导入 → verify 验证`。

### 2.3 `GET /api/v1/data-hub/capabilities`

返回 `schema_major`、`sources[]`、`formats[]`、`auto_detection`、`repair_levels[]`，仅用于开发者选项与能力探测。

## 3. 页面状态定义（全站统一）

| 状态 | 判定 | 展示 |
| --- | --- | --- |
| 加载中 | 请求未返回且无旧数据 | 骨架屏 / `LoadingBlock` |
| 成功有数据 | 请求成功且 `total > 0` | 正常内容 + 结果摘要 |
| 成功但库为空 | `total = 0` 且无筛选条件 | 「还没有…数据」+ 主按钮「同步游戏数据」→ `/data` |
| 筛选无结果 | `total = 0` 且存在筛选条件 | 「没有找到符合条件的球员」+「清除筛选条件」 |
| 失败 | 请求异常 | `ErrorState`：归一化中文原因 +「重试」 |
| 未连接 / 未配置 | 404/405 或能力开关关闭 | 说明性提示，隐藏该模块，不报错 |
| 部分成功 | `status = PARTIAL` | 成功计数 + 警告列表 + 待确认入口 |

禁止：把「库为空」与「筛选无结果」合并为同一句提示；禁止用 Mock 数据填充生产页面。

## 4. 导入进度与状态

- 引擎阶段：`detect → check → match（含 Level 2 身份/俱乐部补全与去重）→ repair → import → verify`，以 `stages[].status` 返回 `pass / warn / blocked / skipped`。
- 修复与隔离写入 `data_repair_audits`（`decision=repaired|quarantined`，只追加）；前端通过 `GET /data-hub/repairs` 展示。
- UI 在请求期间显示不确定进度条与一句说明；返回后展示阶段与计数。
- 任务状态沿用 `/imports` 的 `status`：`succeeded / partial / failed / running / pending / duplicate`，中文映射见 `utils/labels.ts`。
- `import.duplicate = true` 时必须提示「之前已导入过，本次未重复写入」，不得显示为新建成功。

## 5. 错误展示规则

1. 只展示 `ApiError.message`（后端归一化消息）与固定中文标题，**绝不展示堆栈或原始 JSON**。
2. `401`：提示到「系统设置 → 开发者选项」配置令牌。
3. `404/405`（接口未上线）：隐藏模块或提示「当前后端还没有该接口」，不显示为错误。
4. `422`（BLOCKED）：展示检测原因与隔离行摘要。
5. 网络错误：提示「无法连接本地服务」+ 重试。

## 6. Mock 政策

- 允许：Playwright 用例内基于 `page.route` 的接口 Mock，仅用于界面契约测试。
- 禁止：生产代码路径内置 Mock、演示数据或「示例成功」状态。
- 生产环境只走真实接口；Mock 不得进入 `src/`。

## 7. 已知集成缺口（截至本次提交）

| 缺口 | 影响 | 处理 |
| --- | --- | --- |
| 后端没有「触发读取器同步」的接口 | 前端「同步游戏数据」只能检查连接与存档可写状态并给出下一步指引，不能真正拉起同步 | UI 不伪造进度；待数据引擎提供触发接口后接入 |
| 备份/恢复没有接口 | 设置页只展示真实数据目录与备份说明 | 不提供假按钮 |
| 更新检查没有接口 | 设置页只展示当前版本与更新方式 | 不提供假按钮 |
