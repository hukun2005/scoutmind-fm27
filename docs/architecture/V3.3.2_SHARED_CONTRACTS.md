## 1. 球员统一身份

| 字段 | 说明 |
|---|---|
| `player_id` | 跨存档的球员身份（`players.id`），不携带存档 ID |
| `instance_id` | 存档内的球员实例（`player_instances.id`），详情/关注/引援/对比统一使用 |
| `save_id` | 存档隔离字段；所有查询必须以服务端注入的存档为准 |
| `build` / `save_local_uid` | 存档内业务标识；**不得**用姓名作为唯一主键 |
| `latest_snapshot_id` | 新增：指向该实例最新快照；缺失时回退到聚合查询 |

所有前端跳转只使用 `navigation_target`（`/players/<instance_id>`），跳转后详情页重新按 `instance_id + save` 校验身份。

## 2. 查询服务

- 球员列表/搜索/详情：`app.analytics.players`（`list_players` / `player_profile` / `latest_snapshot_subquery`）
- 阵容：`app.analytics.squad`（`roster` / `squad_overview` / `position_depth` / `squad_weakness`）
- 引援：`app.analytics.recruitment_recommend.recommend`（与引援中心同一评分服务）
- 关注：`app.services.watchlist`
- 搜索、AI 足球总监**只能调用上述服务**，不得复制一套评分或阵容规则。

## 3. 最新快照契约

- 新增列 `player_instances.latest_snapshot_id`（普通整数引用，避免 `instances ↔ snapshots` 循环外键）。
- 写入：导入器创建快照后，只有 `observed_at` 不早于上一次 `last_seen_at` 时才更新引用；重复快照时若引用为空则补上。
- 回填：migration 按 `(observed_at DESC, id DESC)` 回填每个实例的最新快照。
- 读取：`latest_snapshot_subquery` = 有引用走主键 JOIN；引用为空的历史数据回退到原聚合，保证旧库与测试数据行为不变。
- 历史快照、属性值、原始字段不做任何覆盖。

## 4. 搜索契约（`GET /api/v1/search`）

- 参数：`q`（≤64）、`type`（`all|players|clubs|transfers|watchlist`）、`limit`（1–20）、`save_id`（可选，默认服务端当前存档）。
- 响应：`categories` 固定包含 `players`、`clubs`、`transfers`、`watchlist` 四个数组（未请求的分类为空数组）。
- 结果项：`entity_type`、`entity_id`、`display_name`、`subtitle`、`navigation_target`、`meta`。
- 球员：姓名、位置代码、当前俱乐部名称；俱乐部：名称、国家、联赛；转会：球员、买方、卖方、日期、类型/状态；关注：球员 + 名单 + 状态。
- LIKE 通配符按字面量转义；空查询不扫描数据表；不同存档不混合；同名球员用 `entity_id`（instance_id）+ 存档上下文区分。
- 前端 `Ctrl+K`、↑/↓、Enter、Esc、防抖 280ms、请求序号丢弃过期响应；最近搜索与最近访问只存本地 `localStorage`。

## 5. AI 足球总监契约

- `GET /api/v1/agent/director/context`：当前存档、俱乐部、数据更新时间、数据完整度、阵容/转会/关注规模，缺失即 `null` 并给出 `data_gaps`。
- `POST /api/v1/agent/director/ask`：`{question, instance_id?, club_id?}`；服务端注入 `save_id`，拒绝请求体中的 `save_id`。
- 回答结构（与既有 AI 助手一致）：
  - `conclusion`：核心结论
  - `sections[]`：数据依据 / 推荐 / 风险 / 数据缺失，每节带 `reliability`（fact / computed / inference / unavailable）
  - `recommendations[]`：`{instance_id, name, reason, actions[]}`
  - `player_cards[]`：只来自工具真实返回的 `instance_id`
  - `data_gaps[]`、`citations[]`、`tools[]`、`mode`（`deterministic-rules` / `llm-planned`）
- 离线可用：无 LLM 时规则引擎照常回答，并声明 `mode=deterministic-rules`；不得宣称离线大模型能力。
- 建议只做展示，不自动改球员、关注或转会状态。
- 切换存档后前端清空上下文；后端每次调用都按当前存档重新取数。

## 6. 缓存契约

- 键：`(save_id, data_revision, 逻辑名, 参数)`；`data_revision = (max snapshot id, max instance id, max transfer id)`。
- 失效：数据版本变化立即失效；另有 60s TTL；只缓存可重算的纯统计结果（覆盖度、阵容统计、引援评分）。
- 禁止缓存跨存档数据、禁止缓存错误结果；关注项/备注不做缓存（本身已是单查询）。
