# ScoutMind V3.2.5.1 静态根指针分析

日期：2026-11-24 · 环境 FM27 27.1.0 / build 26620374 · pid 60012

## 1. 方法

新增 `static-date-scan --expect <date> [--depth 1|2]`：

```text
game_plugin / GameAssembly 模块区域（由 Phase 0 的 Bounds 提供）
    → 8 字节对齐指针（必须指向堆，模块内引用跳过）
    → 目标对象前 4 KiB（第 2 跳再读容器前 0x200）
    → 与期望日期逐位相等的 u32
```

`date-read --rva <RVA> --field <偏移>` 用于按“模块基址 + RVA”重新读取，验证跨重启可复用性。

## 2. 结果：只找到一条静态根

```text
game_plugin + RVA 0x5CE040
    → 堆对象（1 跳）
    → +0x1E4 = 2026-10-25（读到时游戏日期）
```

扫描预算 512–768 MiB（覆盖 game_plugin 392 MB + GameAssembly 60 MB），
`--depth 2` 下**仍然只有这 1 条根**，没有其他模块静态指针能到达“含日期的对象”。

## 3. 这条根为什么不能作为“当前日期”

对同一目标对象做全量日期转储，发现它是一个**日历/赛程结构**，同一对象内同时存在：

```text
+0x0B4 2026-10-24
+0x1E4 2026-10-25
+0x314 2026-10-17
+0xEF4 2026-10-26
+0x080 2027-05-14 / 2026-06-29 / 2026-08-07 / 2026-12-10 / 2026-12-31（成组重复）
```

这些固定日期成组重复出现，说明它是赛季日历/赛程条目表，不是“当前日期”字段。

## 4. 交叉验证失败

用户确认游戏日期为 2026-10-26 后：

- `date-read --rva 0x5CE040 --field 0x1E4` 仍读出 **2026-10-25**（+0x1E4 并未随日期推进更新）；
- 同一对象内 10-26 出现在 +0xEF4，属于日历条目；
- 用 `date-locate` 搜索“日期 + 参考日期 + 0xFFFFFFFF + 两个 0”签名，127 处命中中
  **没有一处**的日期是 2026-10-26。

因此这条静态根 **不能** 作为当前游戏日期来源，状态保持 `unverified_candidate`。

## 5. 结论与下一步

- 模块边界问题已解决（Phase 0/1），`date-read` 的“RVA 链”机制本身可用；
- 但**世界时钟对象的静态根尚未找到**；
- 下一步应改用“差分定位”：在同一静态根可达的对象集合里，比较两个游戏日期的快照，
  找出“值按 +1 日序推进”的字段，而不是按日期值直接匹配（当前匹配命中的是日历条目）；
- 在找到并跨两日期验证之前，自动历史快照保持 BLOCKED。
