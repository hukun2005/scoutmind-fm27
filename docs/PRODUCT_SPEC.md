# ScoutMind 产品规格

## 1. 定位

ScoutMind 是独立于 Football Manager 27 的智能球探、球员成长追踪、转会市场分析与俱乐部经营决策平台。
它把游戏里“看不到长期记忆”的信息变成可查询的数据资产：跨赛季的球员快照、可追溯的成交行情、可解释的角色评分。

产品目标：个人长期使用 → 开源项目 → 未来商业化（多用户、云同步为预留能力，MVP 不引入）。

## 2. 产品原则

| 原则 | 落地方式 |
| --- | --- |
| 事实与推断分离 | 每条记录带 `source`；成长归因分 `fact` / `correlation` / `speculation` 三类展示 |
| 数据可追溯 | `observed_at`、`imported_at`、`game_date`、`reader_version`、`game_build`、`coverage`、`confidence` 落库 |
| 未知值保持 NULL | 导入与 API 全链路不填默认值；界面显示 `—` |
| 统计优先于语言模型 | 所有数字由 `app/analytics` 计算，AI 只编排工具和解释结果 |
| 渐进式交付 | 先读取与快照，再做统计与 UI，最后接 LLM |

## 3. 功能模块

| 模块 | 当前状态 | 说明 |
| --- | --- | --- |
| 球员数据中心 | 已实现 | 身份层 `players` 与存档层 `player_instances` 分离，快照追加 |
| 成长追踪中心 | 已实现 | 关注列表、标签、成长曲线、归因、自动提醒规则 |
| 智能球探中心 | 已实现 | 8 个战术角色模板，按角色加权评分并展示覆盖度与短板 |
| 转会决策中心 | 部分实现 | 估值区间、报价模拟、同类成交分位；现金流与分期预算待补 |

## 4. 关键用户场景

1. **历史成交价格问答**：「20 岁、CA 145、PA 175 的前锋，历史上类似球员卖多少钱？」
   → 工具返回样本数、中位数、25/75 分位、覆盖率；回答必须报告样本不足。
2. **报价建议**：「目标身价 3000 万，卖方要 4000 万，我该出多少？」
   → 估值区间 → 首报 / 目标价 / 上限，并说明合同年限调整。
3. **俱乐部画像**：「哪些俱乐部经常低价买入年轻球员、再高价卖出？」
   → 买入/卖出笔数、净投入、年轻化比例、已实现利润。
4. **出售窗口**：「我队这名年轻球员是否到了合适的出售窗口？」
   → 估值区间 + 当前 CA/PA + 合同剩余 + 同类成交分位。
5. **成长追踪**：多次扫描后看到 CA 与身价曲线，停滞与合同到期触发提醒。

## 5. AI 回答规范

- 必须说明检索到多少笔交易与筛选条件。
- 优先给中位数与四分位，不给单一“准确价格”。
- 列出可比交易明细（球员、日期、买卖方、成交价、相似度）。
- 说明金额口径：基础费用 / 已支付 / 未来分期 / 已触发附加 / 潜在附加分别处理。
- 指明缺失字段、覆盖率和样本偏差。
- 样本不足时明确拒绝给出估值，并给出放宽条件的建议。
- 结论是决策辅助，不是游戏内真实报价。

## 6. 验收基线

| 维度 | 标准 |
| --- | --- |
| 读取 | 兼容版本下可扫描；未知构建安全拒绝；未启动游戏返回 NotFound 且不崩溃 |
| 导入 | 同一 `scan_id` 重复导入幂等；两次扫描产生两份快照且旧数据不被覆盖 |
| 交易 | 只有 `status=completed` 且带金额的交易进入统计；未触发附加条款不计入已支付 |
| 分析 | 统计显示样本数、覆盖率、算法版本；样本 < 5 时拒绝估值 |
| AI | 回答中的每个数字都能在工具结果里找到；固定问题回归集通过 |
| 安全 | API 仅本地监听；可选令牌校验；读取器只读且拒绝未知版本 |
